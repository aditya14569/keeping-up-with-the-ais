# Part 1 · Learn one thing

## 🧠 The KV cache: a model's short-term memory

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 7 · NEWER TECHNIQUES</span>

**Every time a chatbot writes one more word, it has to look back at everything before it. The KV cache is what stops that from being painfully slow.**

**The plain-English version.** A model writes one token at a time. To pick the next token, attention compares it with **every earlier token**. Each earlier token is turned into two vectors: a **key** (what it's about) and a **value** (what it says). Those never change, so instead of recomputing them for every new word, the model **saves them in memory**. That saved pile is the **KV cache**. [(Hugging Face)](https://huggingface.co/docs/transformers/kv_cache)

**Analogy:** **taking notes in a long meeting.** Without notes, every time someone asks a question you'd **replay the whole recording** from the start. With notes, you just glance at your notepad. The catch: **the notepad keeps growing**, and a three-hour meeting fills a lot of pages.

```viz:versus
left: {emoji: 🔁, title: No cache, points: ["Re-reads the whole text for every new token", "Work grows with every word", "Fine for one sentence, awful for a long reply"], example: "8,000-token prompt → re-run 2,000 times"}
right: {emoji: 🗂️, title: KV cache, points: ["Saves keys and values once", "New token only computes itself", "Costs GPU memory instead"], example: "compute once, look up after"}
note: "The 8,000/2,000 example is from Together AI's explainer."
```

**Memory is the real bill.** The cache grows with **layers × KV heads × tokens**. For Llama 3.1 8B in bf16 it's about **0.125 MiB per token**, so a single 128K-token chat needs **16 GiB just for the cache**. [(Together AI)](https://www.together.ai/blog/kv-cache) That's why long context is priced as a premium, and why serving many users at once is hard.

**So labs shrink it.** The four tricks you'll keep seeing in launch posts:

| Trick | The idea | The catch |
|---|---|---|
| **Multi-query (MQA)** | All query heads share **one** key/value head | Smallest cache, some quality loss |
| **Grouped-query (GQA)** | Groups of query heads share a KV head. Llama 3.1 70B: **64 query, 8 KV** [(Together AI)](https://www.together.ai/blog/kv-cache) | Near full quality, near MQA speed [(arXiv)](https://arxiv.org/abs/2305.13245) |
| **PagedAttention** | Store the cache in small pages, like an OS does with RAM | Needs a serving engine such as **vLLM** [(arXiv)](https://arxiv.org/abs/2309.06180) |
| **Sparse attention** | Each token looks at a **chosen subset** of earlier tokens, not all | Must be trained in to work well [(arXiv)](https://arxiv.org/pdf/2502.11089) |

**The other numbers.** The vLLM paper found older serving systems used only **20–38% of cache memory** for real data; paging cut the waste to near zero and lifted throughput **2–4×**. [(Together AI)](https://www.together.ai/blog/kv-cache) [(arXiv)](https://arxiv.org/abs/2309.06180) DeepSeek's sparse-attention paper claims **up to 11.6× faster decoding** at 64K tokens. [(arXiv)](https://arxiv.org/pdf/2502.11089)

**Why now?** Alibaba's **Qwen4-Max preview** offers a **1M-token** context, Alibaba's **MNN-Pocket** squeezes a model into **173 MB** for phones, and **Ollama 0.40.16** says it cut about **27 GiB** of memory for one model on Macs. [(AI Weekly)](https://aiweekly.co/ai-news-today) [(Sam on AI)](https://samonai.substack.com/p/ai-brief-november-11-2026) All of it is a fight over memory, and the KV cache is a big chunk of that.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Keys and values:** the two vectors each token leaves behind for attention to look up later.
- **Attention head:** one of many parallel "looks" a layer takes at the text. GQA makes heads **share** their keys and values.
- **Prefill vs decode:** prefill reads your whole prompt and **fills the cache**; decode writes the reply one token at a time.
- **Prompt caching:** an API keeping your prompt's cache **between requests**, so repeat prefixes cost less.
</div>

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** in a chatbot, paste a long document and note how long the first reply takes. Ask a follow-up. The second answer usually starts faster: **that's the prompt being cached**, not re-read.
- **Some code:** run the snippet below to price the cache of any open model from its `config.json`.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: size a KV cache in 6 lines**

```python
def kv_gib(layers, kv_heads, head_dim, tokens, bytes_per=2):
    per_token = 2 * layers * kv_heads * head_dim * bytes_per  # K and V
    return per_token * tokens / 2**30
print(kv_gib(32, 8, 128, 131072))   # Llama 3.1 8B  -> 16.0
print(kv_gib(80, 8, 128, 131072))   # Llama 3.1 70B -> 40.0
print(kv_gib(80, 64, 128, 131072))  # 70B, no GQA   -> 320.0
```

**Gotchas:** use `num_key_value_heads`, not `num_attention_heads`, or you'll overestimate by 8×. For cheaper APIs, **put stable text first** (system prompt, docs) and the changing question last; caches only reuse **an identical prefix**. Self-hosting tight on VRAM? Hugging Face supports a **quantized or CPU-offloaded cache**, at some speed cost.
</div>

## Top story 1 · Google's Decisions API: answers, not essays

<span class="tag dev">FOR DEVS</span><span class="tag try">TRY IT TODAY</span>

**What happened.** Google launched the **Gemini Decisions API** and a new model, **Gemini Decision 1**. Instead of writing text, it **scores a fixed set of answers** and returns each with a confidence from 0 to 1. [(Google)](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)


<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Inputs:** text, images, audio, video and PDFs, **up to 256K tokens**.
- **Price:** **$0.10 per million input tokens, $0 for output.** The shared input is **billed once**, however many questions you ask. There's a free tier in AI Studio.
- **Speed:** Google claims **150–250 ms** for inputs up to 16K tokens, nearly flat from 1 to 100 questions.
- **Where:** live in AI Studio; OpenRouter, LangChain, Vercel, LiteLLM and others are **rolling out**.
- **Google uses it** to route Gemini Notebook queries and as a **safety check on MCP tools** in Search.

**The fine print.** It's a crowded lane: OpenAI's Decisions API went GA on **22 Oct** at the same input price, and startup TypeSafe's **Jev** is cheaper at $0.042. An independent index put Decision 1 **9th of 18** at launch, and its edge is **multimodal input**. [(Implicator)](https://www.implicator.ai/google-launches-gemini-decisions-api-powered-new-gemini/) [(The Decoder)](https://the-decoder.com/google-joins-the-decision-model-wave-with-gemini-decision-1-scoring-1000-questions-in-a-single-pass/)

**Why it matters.** A lot of "AI" in real apps is just **classify, route, approve**. Paying a chat model to write a paragraph and then parsing "yes" out of it is slow and costly. **Decision models make those checks cheap enough to run on everything.**

Simon Willison notes Gemini's yes/no scores are **less extreme** than rivals', so don't reuse thresholds tuned on another vendor.

## Top story 2 · Stolen AI keys, a $740,000 bill

<span class="tag watch">SECURITY</span><span class="tag dev">FOR DEVS</span>

**What happened.** Cloud host **Railway** published its full incident report. Attackers stole customer secrets in October and used AI keys among them for about **$740,000 in unauthorised usage**. Railway says it will **pay those charges** where a provider won't refund. [(The Hacker News)](https://thehackernews.com/2026/11/railway-says-stolen-customer-ai-keys.html)

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Scale:** variables decrypted in at most **1.85% of workspaces, about 100,000**, an upper limit. Linked tokens for **1,852 users** were reset.
- **Target:** the attacker's query **hunted for AI provider key names**, also matching cloud, database and payment credentials.
- **Refunds:** AWS and Google have started refunding fraud; OpenAI is case by case; **OpenRouter has a no-refund policy**, so Railway covers it.
- **Pattern:** Wiz counts **at least nine AI developer platforms** that disclosed incidents in October.

**Same week, same theme.** CISA added a **CVSS 9.8** bug in **GPUStack**, an open-source GPU-cluster manager, to its exploited list: before v2.2.0 it treated anything that looked like localhost as **admin**. [(SecurityOnline)](https://securityonline.info/gpustack-authentication-bypass-cve-2026-102895-exploited/) [(AI Weekly)](https://aiweekly.co/ai-news-today) And Microsoft Research showed a backdoor planted by editing **fewer than 10 neurons**, if an attacker can write to the weights. [(Sam on AI)](https://samonai.substack.com/p/ai-brief-november-11-2026)

**Why it matters.** An AI key is **cash with no spending limit** to a thief, and resellers make it easy to turn into money. **Your AI keys are now the most valuable thing in your `.env`.**
