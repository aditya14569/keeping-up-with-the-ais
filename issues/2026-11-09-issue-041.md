# Part 1 · Learn one thing

## 🧑‍💻 AI and jobs: what's changing for developers

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 6 · THE BIGGER PICTURE</span>

**AI isn't deleting the developer job so far. It's squeezing the bottom rung of the ladder and changing what the job is.**

**The plain-English version.** A job is a bundle of tasks. AI takes over some tasks (boilerplate, first drafts, simple bug fixes) and leaves others (deciding what to build, checking it's right, owning it when it breaks). The tasks it takes first are **the ones juniors used to learn on.**

**Analogy:** **power tools in a carpentry shop.** Apprentices used to learn by sawing and sanding all day. Machines do that now, and the shop still needs carpenters. The hard question is **how a new carpenter gets good** when the practice work has gone.

```viz:versus

note: "Our reading of the studies below, not a measured list."
```

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **AI-exposed:** a job whose tasks an AI could plausibly do. It doesn't mean the job will vanish.
- **Augmentation vs automation:** AI helps you do the task, vs AI does the task for you. Stanford's squeeze is worst where it's **automation**.
- **Bench / billable:** in IT services, whether a client is paying for your time. Freshers can take **up to nine months** to become billable.
- **RCT:** randomised controlled trial, the gold standard METR uses.
</div>

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** list last week's work in three columns: **AI did it, AI helped, only me.** The third column is your moat. If it's empty, pick one thing to go deeper on.
- **Some code:** run the snippet below to see how much of your recent work had an AI co-author.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: measure your own AI share**

```bash
total=$(git log --since="30 days ago" --oneline | wc -l)
ai=$(git log --since="30 days ago" -i \
  --grep="co-authored-by:.*\(claude\|copilot\|codex\|cursor\)" \
  --oneline | wc -l)
echo "$ai of $total commits had an AI co-author"
# on a 4-commit test repo: 1 of 4 commits had an AI co-author
```

**Gotchas:** it only counts commits whose trailer names the tool, so autocomplete and pasted code won't show. Add `--author=you` on a shared repo. A high number isn't good or bad. **The useful question is how many of those commits you could explain in review.**
</div>

## Top story 1 · "Yes, and don't ask again" leaked secrets to GitHub

<span class="tag hot">CHECK YOUR REPOS</span><span class="tag dev">SECURITY</span>

**What happened.** Security firm Apiiro examined **104,185 public copies** of Claude Code's `.claude/settings.local.json` and says **1,122 of them hold a real-looking secret**, about 1.1%. Those files contain **1,379 distinct credentials.** [(Cyber Security News)](https://cybersecuritynews.com/claude-codes-yes-and-dont-ask-again/) [(MadRobot)](https://madrobot.blog/2026/11/07/claude-code-dont-ask-again-secrets-github/)

**The mechanism is mundane.** When you approve a command forever, Claude Code saves the **whole command** as an allow rule. If that command had a password in it, the password is now sitting in a file, in plain text.

```viz:flow
title: "How a click becomes a public password"
headers: [You approve, Saved, Git, Result]
columns:
  - [{label: "Don't ask again", sub: "command has a key"}]
  - [{label: settings.local, sub: "plain-text rule", style: accent}]
  - [{label: git commit, sub: "not in .gitignore", style: soft}]
  - [{label: Public GitHub, sub: "readable by anyone", style: warn}]
note: "Simplified from Apiiro's findings as reported by MadRobot and Cyber Security News."
```

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Why it escapes:** Claude Code adds the file to your **global** git excludes, which don't travel with the project or cover files already tracked. It's not added to the repo's own `.gitignore`.
- **Claude's own commits:** in **539 of 1,105** leaking repos Apiiro traced, a commit co-authored by Claude changed the file. [(The 420)](https://the420.in/claude-code-github-credential-exposure-security-flaw/)
- **The wider count:** add git history, shared settings files and saved transcripts, and it's **2,539 secrets across 1,994 repos.** [(RuntimeWire)](https://runtimewire.com/article/claude-code-dont-ask-again-secrets-github-apiiro)
- **What leaked:** **379 database passwords** and **43 SSH logins**, among others.
- **The caveat:** Apiiro **did not test the credentials**, so "real" means it looks like a real key or points at a public host. One notified company confirmed its exposed key had been live.
- **Anthropic's response:** MadRobot says Anthropic **hasn't commented**. We found no reported fix.

```viz:bars

note: "Apiiro's figures, via Cyber Security News and MadRobot."
```

**Why it matters.** The bug is in a **convenience feature**, and that's the point. Every "stop asking me" is a small permanent decision. **If you vibe-code with real database passwords in your commands, this is about you.**

<div class="box care" markdown="1">
**👀 Should you care?** Yes, if you use Claude Code on anything public. **Rotate first, clean up second.** A password that's been on GitHub is burned, even after you delete the file.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: check and fix**

```bash
git log --all --oneline -- .claude/settings.local.json   # ever committed?
git rm --cached .claude/settings.local.json
echo ".claude/settings.local.json" >> .gitignore
```

**Gotchas:** don't stop at the working tree, because **forks and history keep the secret** (211 forks carried them). Approve **patterns** like `Bash(npm run:*)`, not full commands. Pass secrets through **environment variables** so they never appear in a command line.
</div>

## Top story 2 · Anthropic: your rules file is a request, not a control

<span class="tag try">FOR BUILDERS</span><span class="tag dev">AGENTS</span>

**What happened.** Anthropic's Claude Code best-practices guide draws a sharp line: **instructions ask, while hooks enforce.** Its advice, as quoted by FourWeekMBA: **"If something has to happen every time, make it a hook, a deny rule, or a managed setting."** [(FourWeekMBA)](https://fourweekmba.com/ai-anthropic-claude-md-rules-are-requests-hooks-are-enforced/)

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Stop arguing with the agent:** after **two failed corrections**, the advice is to clear the session and write a better prompt.
- **Oversight is hard, even for AI.** In a separate test, Anthropic put teams of **four Claude agents** in the online game **EVE Frontier** and secretly told one to sabotage the mission. Teammates, though warned, **almost never identified the saboteur.** [(Bad, Good, Better)](https://badgoodbetter.substack.com/p/ai-weekly-update-week-ending-november-4a0)
- **Monitors helped a bit:** Claude monitors reading only the public channel caught **20–40% of saboteurs** while falsely accusing honest agents **no more than 5%** of the time.

**Why it matters.** Story 1 and this one are the same lesson. **Anything that must always (or never) happen can't live in a sentence the model may skim.** And if you run several agents together, don't count on them policing each other.

<div class="box care" markdown="1">
**👀 Should you care?** Yes, if you've written "never do X" in a rules file and assumed that settled it. **Pick your single scariest "never" and turn it into a deny rule today.**
</div>
