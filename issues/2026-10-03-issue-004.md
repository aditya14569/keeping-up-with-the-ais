# Part 1 · Learn one thing

## 🎲 Temperature: why the same prompt gives different answers

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 1 · HOW LLMS WORK</span>

**A model doesn't pick the next word. It rolls loaded dice, and temperature decides how loaded they are.**

At every step, a model gives **every possible next token a score**. Those scores become probabilities: "samosa" 49%, "biscuit" 29%, and so on. Then the app has to choose one. Always picking the top token is called **greedy decoding**. Rolling the dice according to the probabilities is called **sampling**, and it's why two people asking the same thing get different replies. [(Hugging Face)](https://huggingface.co/blog/how-to-generate)

```viz:loop
title: How a model writes, one token at a time
center: Your reply
steps:
  - {label: "1 · Score", sub: every possible token}
  - {label: "2 · Reshape", sub: temperature}
  - {label: "3 · Trim", sub: top-k / top-p}
  - {label: "4 · Roll", sub: pick one token}
  - {label: "5 · Append", sub: then go again}
note: Based on the Hugging Face guide to decoding methods. Many APIs now fix steps 2 and 3 for you.
```

**Temperature** reshapes the probabilities before the roll. **Low temperature makes the favourite even more likely**. High temperature flattens things out, so long shots get picked more often. As temperature heads to zero, sampling turns into greedy decoding. [(Hugging Face)](https://huggingface.co/blog/how-to-generate)

```viz:bars
title: "Next word after 'Chai with a side of': how temperature changes the odds"
bars:
  - {label: "samosa · T 0.5", value: 66, display: "66%", highlight: true}
  - {label: "samosa · T 1.5", value: 41, display: "41%"}
  - {label: "cake · T 0.5", value: 0.4, display: "<1%"}
  - {label: "cake · T 1.5", value: 8, display: "8%", highlight: true}
note: "Illustrative: made-up scores for four words, run through the standard softmax-with-temperature formula. At T 1.0 they'd be 49% and 4%."
```

**Analogy:** think of a **cricket captain picking the next bowler**. At low temperature he always tosses the ball to his strike bowler. At high temperature the part-timers get an over: sometimes a wicket, sometimes 20 runs. **Top-k** means "only my best k bowlers are allowed", and **top-p** means "only the bowlers who together cover p% of my confidence".

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Logits:** the raw scores for each possible next token.
- **Temperature:** a knob that sharpens (low) or flattens (high) those probabilities.
- **Top-k:** only sample from the k most likely tokens.
- **Top-p (nucleus sampling):** sample only from the top tokens that add up to p. [(arXiv)](https://arxiv.org/abs/1904.09751)
</div>

### Why now?

Two reasons. First, **newer Claude models no longer let you set it.** Claude's API reference says models released after Claude Opus 4.6 reject any temperature other than 1.0 with a 400 error, and the same goes for `top_p` and `top_k`. [(Claude API Reference)](https://platform.claude.com/docs/en/api/messages/create) Second, today's top story is about **decision models**, which skip the dice roll and hand you the probabilities directly.

### "Temperature 0" isn't a guarantee

Even at zero, answers can drift. Thinking Machines ran one prompt **1,000 times at temperature 0 on Qwen3-235B and got 80 different completions**. They matched for the first 102 tokens and then split. The cause: servers batch your request with other people's, and the maths changes slightly with batch size. [(Thinking Machines)](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference)

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** open three fresh chats and ask the same thing, like "Give me a name for a chai shop." Then ask for something factual, like "What's 17 × 23?" **Creative answers wander; the maths should not.**
- **Some code:** run a small open model locally and change only the temperature:

```python
from transformers import pipeline
gen = pipeline("text-generation", model="gpt2")
for t in (0.2, 1.0, 1.8):
    out = gen("My favourite street food is", do_sample=True,
              temperature=t, max_new_tokens=15)
    print(t, out[0]["generated_text"])
```
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: get consistency without the knob**

Don't rely on temperature for reliability, because on many new models you can't set it. Instead, **constrain the output**: structured outputs or a fixed list of allowed answers, a few examples in the prompt, and validation in code. For a yes/no or pick-one question, a decision model (see Story 1) returns probabilities you can threshold.

**Gotchas:** sending `temperature=0` to a newer Claude model now fails with a 400, so remove it from old configs. [(Claude API Reference)](https://platform.claude.com/docs/en/api/messages/create) When you test a prompt, **run it several times**. One good answer at temperature 1 proves very little.
</div>

## Top story 1 · Jev gets three open-weight rivals in one day

<span class="tag hot">BIG DEAL</span><span class="tag dev">DEVS: TRY IT</span>

**What happened.** On 1 October, three companies released **decision models**: AI models that don't write text, but answer questions like "is this urgent?" or "which team gets this ticket?" with probabilities. **Cloudflare launched Clef and Clef-flash** [(Cloudflare)](https://blog.cloudflare.com/clef-decision-models/), **Perplexity launched a Decisions API** on its own open model [(Perplexity Docs)](https://docs.perplexity.ai/docs/decisions/quickstart), and **AWS's Strands team released a 2B model** small enough for a laptop. [(Strands Agents)](https://strandsagents.com/blog/introducing-strands-decider/) All three are open-weight and aim at TypeSafe's Jev, which we covered in Issue #1.

| Model | Size | Runs where | Claimed edge |
|---|---|---|---|
| ☁️ **Cloudflare Clef** | 27B (flash: 9B) | Workers AI or your GPUs | Also reads images; 64K context |
| 🔎 **Perplexity Decider** | 27B | Perplexity API or your GPUs | 85.71% vs Jev's 84.51% on 11 tests |
| 🧵 **AWS Strands Decider** | 2B | Your laptop | ~153 ms on an M3 MacBook |

**The details that matter:**

- **Speed is the pitch.** Cloudflare reports median latency of **38.8 ms for Clef-flash and 209.3 ms for Clef, against 524.1 ms for Jev**. [(Cloudflare)](https://blog.cloudflare.com/clef-decision-models/) These are the company's own tests.
- **Mixed scorecards.** Perplexity's model card shows it beating Jev overall and by a wide margin on RAGTruth (88.80% vs 77.27%), but Jev still leads on some tests. [(Hugging Face)](https://huggingface.co/perplexity-ai/pplx-decider-v1-27b) The Register notes Clef's results aren't yet on the independent Decision Index leaderboard. [(The Register)](https://www.theregister.com/ai-and-ml/2026/10/01/cloudflare-tries-to-outplay-jev-with-open-weight-clef-models/5300649)
- **Most open, smallest:** AWS released Strands Decider's **training data and scripts too**, and you install it with `pip install strands-decider`. [(Strands Agents)](https://strandsagents.com/blog/introducing-strands-decider/)
- **Hardware reality:** self-hosting Clef-flash needs about **41GB of GPU memory**, and full Clef about 85GB. [(The Register)](https://www.theregister.com/ai-and-ml/2026/10/01/cloudflare-tries-to-outplay-jev-with-open-weight-clef-models/5300649)

**Why it matters.** A huge share of "AI features" are really **sorting decisions**: route this, flag that, is this spam. A chat model writing "Yes, I think..." is slow and hard to parse. A decision model gives you `0.93`, in milliseconds, for almost nothing. **When three companies copy a format in one day, it's becoming a standard.**

<div class="box devs" markdown="1">
**🛠️ For devs: one request, many answers.** Perplexity's API takes your content as `state` plus up to 128 named questions. Each is a yes/no (`noul`), a `choice`, or a `score`. [(Perplexity Docs)](https://docs.perplexity.ai/docs/decisions/quickstart)

```python
httpx.post("https://api.perplexity.ai/v1/decisions",
  headers={"Authorization": f"Bearer {KEY}"},
  json={"model": "pplx-decider-v1-27b",
        "state": {"review": "Battery died after two weeks."},
        "questions": {"defect": {"type": "noul",
          "instructions": "Does the review report a defect?"}}})
```

Cloudflare's Clef uses the same `state` and `questions` shape. [(Cloudflare)](https://blog.cloudflare.com/clef-decision-models/) **Gotcha:** a probability isn't a decision. Pick your threshold on real data, then re-check it when you swap models.

## Top story 3 · Claude Code gets "mods" you write in TypeScript

<span class="tag dev">DEVS</span><span class="tag try">TRY IT</span>

**What happened.** Anthropic added **mods** to Claude Code on 1 October. A mod is a small TypeScript or JavaScript file that can **rewrite a prompt, block or retry a tool call, redact secrets from output, or add buttons and panels** to the interface. Mods ship inside plugins, and you can just ask Claude to write one for you. [(Claude Blog)](https://claude.com/blog/claude-code-mods)

```viz:flow
      sub: panes, buttons
      style: warn
note: Simplified from the Claude blog and the "Create a mod" docs. Mods need Claude Code v2.1.287 or later.
```

**The details that matter:**

- **Not sandboxed.** Mods run with the **same access to your machine as Claude Code itself**, so only install ones you trust. [(Claude Blog)](https://claude.com/blog/claude-code-mods)
- **Guardrail for teams:** a built-in `sec-default` mod loads first on Team and Enterprise machines and stops user mods from **overriding permission deny rules**. [(Claude Blog)](https://claude.com/blog/claude-code-mods)
- **Fast loop:** load a folder with `claude --plugin-dir ./my-mod` and it **hot-reloads when you save**. `claude plugin validate` and `claude plugin test` check it without a live session. [(Claude Code Docs)](https://code.claude.com/docs/en/plugins/mods/create)

**Why it matters.** Until now, changing how a coding agent behaved meant settings files and shell-script hooks. Mods make the agent **programmable from the inside**, the way browser extensions made browsers programmable. Timely too, given Story 2: a mod that blocks risky commands is a guardrail you control.

<div class="box devs" markdown="1">
**🛠️ For devs: the 10-line version.** The docs' starter mod counts tool calls. Each hook gets the mods API (`$`), the event (`e`), and `next`, which passes the event on. [(Claude Code Docs)](https://code.claude.com/docs/en/plugins/mods/create)

```javascript
let calls = 0
export function register(on) {
  on('tool.call', async ($, e, next) => {
    calls += 1
    return next(e)   // let the tool run as usual
  })
}
```

Return your own result instead of calling `next` to block a call. **Gotcha:** write event names as string literals, or validation fails.
