# Part 1 · Learn one thing

## 🏎️ Speculative decoding: let the intern guess, let the boss check

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 7 · NEWER TECHNIQUES</span>

**Big models are slow because they write one token at a time. Speculative decoding lets a tiny model run ahead, and the big model checks its guesses in one go.**

**The plain-English version.** Yesterday we saw that a model writes **one token per step**, and every step means running the whole big model. But checking a few tokens costs about the same as writing one, because the big model can look at **several positions in parallel**. So a small, fast **draft model** guesses the next few tokens, and the big **target model** verifies them all at once. Correct guesses are kept for free. [(arXiv)](https://arxiv.org/pdf/2211.17192)

**Analogy:** **a junior writing a first draft for a senior editor.** The junior types the next sentence quickly. The editor reads it in one pass, keeps every word up to the first mistake, fixes that word, and hands it back. When the junior is good, the editor barely has to write anything.

```viz:loop
title: "One round of speculative decoding"
center: Same output as the big model alone
steps:
  - {label: "1 · Draft", sub: small model guesses ~5 tokens}
  - {label: "2 · Verify", sub: big model scores all in one pass}
  - {label: "3 · Accept", sub: keep guesses up to first miss}
  - {label: "4 · Fix", sub: big model adds one token of its own}
note: "Simplified from Leviathan et al. (2023) and Baseten's explainer."
```

**The trick that keeps it honest.** Guesses aren't accepted blindly. Each one is compared with what the big model would have picked, using a rule called **rejection sampling**. The paper proves the result has **exactly the same output distribution** as running the big model alone. It's a speed-up, **not an approximation.** [(arXiv)](https://arxiv.org/pdf/2211.17192) [(Baseten)](https://www.baseten.co/blog/a-quick-introduction-to-speculative-decoding/)

**The napkin maths.** Baseten's example: the big model takes **10 ms per token**, the draft takes 1 ms. Draft 4 tokens (4 ms), verify (1 ms), add the big model's own token (10 ms). If 2 drafts survive on average, you get **3 tokens in 15 ms: 5 ms each, twice as fast.** [(Baseten)](https://www.baseten.co/blog/a-quick-introduction-to-speculative-decoding/)

**Bigger draft isn't better.** In the original paper, with an 11B T5 model as the boss, the **smallest** draft won. A bigger draft guesses right more often, but it's slower to run, which eats the gain.

```viz:bars
title: "Speed-up on English→German translation (T5-XXL target)"
bars:
  - {label: "T5-small (77M) · 75% kept", value: 3.4, display: "3.4×", highlight: true}
  - {label: "T5-base (250M) · 80% kept", value: 2.8, display: "2.8×"}
  - {label: "T5-large (800M) · 82% kept", value: 1.7, display: "1.7×"}
note: "Source: Leviathan et al., Table 2 (greedy decoding, batch size 1, one TPU-v4)."
```

**Why now?** Every lab is selling a **fast tier**. Google calls Hydrogen "built for rapid execution", and Moonshot says Kimi K3.1 Pro Highspeed writes **2–3× faster** than the regular version. [(SiliconANGLE)](https://siliconangle.com/2026/11/12/google-releases-gemini-4-hydrogen-a-lower-cost-model-said-to-outscore-argon/) [(Implicator)](https://www.implicator.ai/llm-meter-week-of-nov-12-2026/) Labs rarely say how, but drafting ahead is **one of the standard tools** for this.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Draft model:** a small, fast model (same tokenizer) that proposes the next few tokens.
- **Acceptance rate:** the share of drafted tokens the big model keeps. Higher means faster.
- **Lossless:** the final text follows exactly the same probabilities as the big model on its own.
- **MTP (multi-token prediction):** models like DeepSeek-V3 are trained to guess several tokens themselves, so they **draft without a second model.**
</div>

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** ask a chatbot to **repeat a long paragraph back with one word changed**. Copy-heavy replies are where drafting shines, because the guesses are easy, and you'll often see the text pour out.
- **Some code:** run the Hugging Face snippet below with a 1.7B model and its 135M sibling, and time it with and without the assistant.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: turn it on in two places**

```python
# Hugging Face Transformers
out = model.generate(**inputs, assistant_model=small_model)
# no second model? copy-from-prompt drafting
out = model.generate(**inputs, prompt_lookup_num_tokens=5)
```

In **vLLM**, pass a `speculative_config` with a `method` (draft model, n-gram, EAGLE, MTP) and `num_speculative_tokens`. Our sandbox run of the paper's formula: at **5 drafted tokens**, a 50% acceptance rate yields **1.97 tokens per big-model pass**, 75% yields **3.29**. [(Hugging Face)](https://huggingface.co/docs/transformers/en/assisted_decoding.md) [(vLLM)](https://docs.vllm.ai/en/latest/features/speculative_decoding/index.html)

**Gotchas:** the draft must share the **tokenizer**. Hugging Face's version doesn't support **batched inputs**. It helps most at **small batch sizes**: on a busy server the GPU is already full, so Baseten warns it can **cut total throughput**. vLLM's "FLy" option relaxes the check, so it is **not lossless**.
</div>

## Top story 3 · OpenAI's Daybreak: agents that attack, agents that patch

<span class="tag watch">SECURITY</span><span class="tag dev">FOR DEVS</span>

**What happened.** At its **Cyber at the Frontier** keynote, OpenAI launched two products built on lessons from defending itself: **Daybreak Red Team**, which tests whether a flaw is **actually exploitable**, and **Daybreak Defense Factory**, which turns findings into **proposed patches**. [(The Deep View)](https://www.thedeepview.com/articles/openai-sees-a-new-enterprise-frontier-in-cyber)

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Red Team:** a coordinating agent splits the job, others dig through code and app context, and **reviewer agents double-check**. The point is to rank which bugs to fix first.
- **Defense Factory:** builds on **Codex Security**, which scans code as it changes, flags issues to the right engineer and **proposes a fix in Codex**.
- **Access:** Red Team is in **early access** with a waitlist; Defense Factory ships via the **Daybreak plugin in Codex**. **No pricing yet.**
- **Open source too:** the Codex Security CLI and a TypeScript SDK are reportedly **open-sourced**, with v0.10.0 adding resumable scans and a **cost cap**. [(DEV Community)](https://dev.to/hiroki-ii-ai/ai-daily-digest-november-13-2026-gemini-4-hydrogen-goes-default-googles-gemini-glasses-open-2a94)

**Why it matters.** AI is finding bugs faster than teams can fix them: last week's GPT-6 Cyber and the Linux kernel work showed that. **The bottleneck is now patching**, and that's exactly where OpenAI is pointing agents.
