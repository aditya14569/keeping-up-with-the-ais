# Part 1 · Learn one thing

## 🧮 Cost modelling: what does one user actually cost you?

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 4 · SHIPPING FOR REAL</span>

**Before you price your AI app, you need one number: what an average user costs you per month, and what your heaviest users cost.**

**Cost modelling** means turning "we call an LLM" into a rupee figure. Every request has **input tokens** (your system prompt, the chat history, any documents) and **output tokens** (the reply). Each has a price per million tokens. Multiply by how often people use the feature, and you have your bill.

**Analogy:** **running a thali restaurant.** The menu price is easy to see. The real question is what each plate costs: rice, dal, the refills people ask for, and the one regular who eats four helpings. **Your system prompt is the rice: it goes on every plate.** Heavy users are the refills.

```viz:flow
title: "From tokens to a monthly bill"
headers: [1 · Per request, 2 · Price, 3 · Usage, 4 · Reality]
columns:
  - [{label: Input tokens, sub: "prompt + history", style: soft}, {label: Output tokens, sub: "the reply", style: soft}]
  - [{label: × price / 1M, sub: "output costs more", style: accent}]
  - [{label: × requests, sub: "per user per month", style: accent}]
  - [{label: × overhead, sub: "retries, agents", style: warn}]
note: "Cost per request = (input tokens ÷ 1M × input price) + (output tokens ÷ 1M × output price). Formula as given by CloudZero and LLM Gateway."
```

**Output usually costs more.** CloudZero's guide says output tokens typically cost **about five to six times** as much as input. So a chatty model that writes long answers can cost more than one that reads long documents. [(CloudZero)](https://www.cloudzero.com/blog/llm-cost-calculator/)

**A worked example.** Say your feature sends **2,000 input tokens** and gets back **500 output tokens**, using Mistral Large 4's listed API price of **$0.70 in / $2.10 out** per million. [(AI Weekly)](https://aiweekly.co/ai-news-today) That's about **$0.0025 a request**. At 20 requests a day, one user costs **about $1.47 a month**.

```viz:bars
title: "One user, one month: three ways to count"
bars:
  - {label: Naive estimate, value: 1.47, display: "$1.47"}
  - {label: "With 1.5x overhead", value: 2.21, display: "$2.21", highlight: true}
  - {label: "With prompt caching", value: 0.90, display: "$0.90"}
note: "Illustrative, our own maths: 2,000 in / 500 out tokens, 600 requests a month at $0.70/$2.10 per million. The 1.5x is LLM Gateway's rule of thumb for retries and extras. Caching assumes 1,500 input tokens are cached and billed at ~10% of the normal rate (CloudZero)."
```

**The traps.** LLM Gateway suggests multiplying your naive estimate by **1.5 to 2** for retries, failures and extra calls. [(LLM Gateway)](https://llm.svc-utility-belt.optimizely.com/blog/how-to-estimate-llm-token-costs) Agents are worse: CloudZero says one coding-agent task can use **400,000 to 2 million** input tokens in total, because every step re-reads the context.

**The averages lie.** Metabase's advice is to track **cost per active user** and also the **95th-percentile user**, who "always costs several times the average." [(Metabase)](https://www.metabase.com/metrics/llm-cost-per-user) If you sell a flat ₹299 plan, that heavy user decides whether you make money.

**Why now?** Today's Part 2 story is about Big Tech spending more on AI than it brings in. Promo prices and generous plans **won't last forever**. Build your model so you can rerun it when prices change.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Unit economics:** the money in and out **per unit**, here per user or per request.
- **Prompt caching:** reusing the same prompt prefix so the provider bills it at a **much lower rate** (Issue #11).
- **Batch API:** send jobs that can wait hours; CloudZero says most providers give **50% off** for it.
- **p95:** the value that 95% of users are below. It shows **your expensive tail**.
</div>

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** open a spreadsheet. Columns: input tokens, output tokens, price in, price out, requests per user per day. Fill in your best guesses and **multiply by 30**. Then double the requests for a "power user" row.
- **Some code:** log the `usage` field from 20 real API calls (every major API returns token counts), then plug the averages into the snippet below.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: a 10-line cost model**

```python
PRICE = {"in": 0.70, "out": 2.10}          # $ per 1M tokens: use your model's
def cost(inp, out, cached=0, cache_rate=0.1):
    fresh = inp - cached
    return (fresh * PRICE["in"] + cached * PRICE["in"] * cache_rate
            + out * PRICE["out"]) / 1e6
per_req = cost(2000, 500)
for name, reqs in {"median": 20, "p95": 120}.items():
    month = per_req * reqs * 30 * 1.5    # 1.5x overhead
    print(f"{name}: ${month:.2f}/user/month")
```

**Gotchas:** your **system prompt is billed on every call**, so trim it or cache it. Some models charge **more above a context size** (CloudZero gives examples above 200K tokens). Use **real token counts from the response**, not word counts. And **segment by plan**: free users are a marketing cost, not your margin.
</div>

## Top story 1 · A fake Claude Code update backdoored Cursor users

<span class="tag hot">SECURITY</span><span class="tag dev">FOR DEVS</span><span class="tag try">ACT NOW</span>

**What happened.** A trojanized **version 2.1.313** of Anthropic's Claude Code extension went up on the **Cursor Marketplace** under the real ID `anthropic.claude-code`, so it looked like a normal update. Cursor says **at most 5,000 users** installed it, between about **14:57 IST on 29 Oct and 02:05 IST on 30 Oct**. Cursor says Anthropic didn't build it. [(The Hacker News)](https://thehackernews.com/2026/10/official-claude-code-vs-code-extension.html)

```viz:flow

note: "Per The Hacker News and Cursor's analysis. The SSH step usually fails on Mac and Windows without admin rights; the other steps still run."
```

**The details that matter:**

- **How it hid:** a **66-line loader** was placed in front of the real extension code, so the tool still worked normally. How attackers got it published is **still unclear**.
- **What it took:** your IP, hostname, username, OS, git email, and the **names (not values)** of up to 40 environment variables with words like KEY, TOKEN or AWS. That's a map of what to steal next.
- **Who's safe:** there's **no evidence** it reached Open VSX or Microsoft's VS Code Marketplace. Anthropic shipped a clean **2.1.314**, and Cursor temporarily shut its marketplace and says it will contact affected users.

**Why it matters.** Last week a CLI was hijacked; this week an AI extension. **Auto-update is a trust pipe**, and attackers are aiming at the tools that already hold your keys.

## Top story 3 · Update: Indian lenders count the cost of AI-agent attacks

<span class="tag hot">INDIA</span><span class="tag dev">SECURITY</span><span class="tag watch">UPDATE</span>

**What happened.** Two weeks after **CERT-In's warning** that autonomous AI agents were attacking Indian systems (Issue #18), the first losses are emerging. Per Economic Times reporting cited by Sify, **smaller NBFCs** (non-bank lenders) lost an estimated **₹300 crore over about two months**, with nearly **150 complaints or FIRs**. Victims aren't named. [(Sify)](https://www.sify.com/ai-analytics/black-october-gets-worse-ai-attacks-hit-india-forcing-cert-in-to-issue-security-alert/)

**The details that matter:**

- **Old mistakes, new speed:** CERT-In's list is familiar: **exposed API keys**, forgotten test APIs, keys stored in plain text, over-broad cloud roles, admin panels **without 2FA**. Agents just find them faster, cutting the time from break-in to damage **from days to hours**.
- **They come back:** attackers revisited targets within days, and agents **reused credentials** they had already found.
- **Nobody noticed:** per CERT-In, the hit organisations **didn't detect the access themselves**. AI providers reported many incidents from their own testing.
- **Named tool:** investigators found a platform called **"CyberStrike"** in some finished cases.

**Why it matters.** This is the same story as Top story 1 from the other side: **leaked secrets are what AI attackers feed on**. Indian fintech and SaaS teams are clearly in range.
