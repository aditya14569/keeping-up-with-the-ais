# Part 1 · Learn one thing

## 👥 Multi-agent systems: one boss, or a team of equals?

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 8 · REAL-WORLD AI</span>

**Instead of one AI doing everything, you split the job across several AI "agents", each with its own instructions, tools and context. The big design question is who's in charge.**

**The plain-English version.** A **multi-agent system** is several LLM agents working on one goal. There are two common shapes. In a **coordinator** setup (also called orchestrator-worker or manager), one lead agent breaks the job up, hands out pieces and writes the final answer. In a **peer team**, agents pass control to each other (a **handoff**), or all read and write a shared board, and no single agent owns the result.

**Analogy:** a wedding. A **planner** (coordinator) calls the caterer, the florist and the DJ, then makes sure it all fits together. Or the **families just split the jobs** (peers): faster to start, but you may end up with two cakes and no chairs.

```viz:versus
left:  {emoji: 🧭, title: "Coordinator", points: ["Lead agent splits the task", "Workers report back to it", "Lead writes the final answer", "Easier to debug and control"], example: "planner → [search, search, search] → report"}
right: {emoji: 🤝, title: "Peer team", points: ["Agents hand off or share a board", "Whoever holds control replies", "Flexible, fewer bottlenecks", "Easier to make conflicting choices"], example: "triage → billing → refunds"}
note: "Our simplified comparison. OpenAI's Agents SDK calls these 'agents as tools' (manager) and 'handoffs'."
```

**Does it actually help?** For the right job, a lot. Anthropic's research feature uses a lead Claude agent that spawns subagents to **search in parallel**. On its internal research eval, that setup beat a single agent by **90.2%**, and parallel work cut research time by up to 90% on complex queries. [(Anthropic)](https://www.anthropic.com/engineering/multi-agent-research-system)

**The catch is cost.** In the same post, Anthropic says agents use **about 4× the tokens** of a chat, and multi-agent systems **about 15×**. Token spend alone explained 80% of the score differences on one benchmark. More agents often just means more thinking you pay for.

**When it goes wrong.** Cognition, the Devin maker, argues **against** splitting most work. Its example: ask two subagents to build a Flappy Bird clone, one doing the background and one the bird. You get a **Mario-style background and a bird that moves wrong**, because each made choices the other never saw. Its rule: **share full context, because every action carries hidden decisions.** [(Cognition)](https://cognition.com/blog/dont-build-multi-agents)

**The useful middle ground**, from LangChain's Harrison Chase: teams that mostly **read** (research, search, review) parallelise well. Teams that **write** the same thing (code, one document) clash. [(LangChain)](https://www.langchain.com/blog/how-and-when-to-build-multi-agent-systems)

**Why now?** Story 1. ARTEX, the attack tool Microsoft just dissected, is a coordinator design: a **planner** issues small "intents", **workers** carry them out, and everything lands on a shared **knowledge graph**. Attackers picked the "reading-heavy" pattern that works best.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Orchestrator / coordinator:** the lead agent that plans, delegates and merges results.
- **Subagent / worker:** an agent given one narrow task and its own fresh context.
- **Handoff:** passing the conversation, and the job of replying, to another agent.
- **Blackboard:** a shared store (notes, a graph, a database) that all agents read and write.
</div>

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** in Claude Code, Codex or a similar tool, ask for a **research** task ("compare three Indian UPI SDKs") and tell it to use subagents. Then try a **writing** task the same way. Which result holds together better?
- **Some code:** run the toy below, then delete the shared `decisions` line and watch the mismatches come back.
</div>

<div class="box devs" markdown="1" style="break-inside: avoid">
**🛠️ For devs: write the decisions down before you fan out**

```python
def worker(part, decisions, rng):
    style = decisions.get("style") or rng.choice(STYLES)
    return f"{part}:{style}"

decisions = {"style": "pixel-art"} if shared else {}
out = pool.map(lambda p: worker(p, decisions, rng),
               ["background", "bird", "pipes"])
# shared decisions=False: 9.0% of 1,000 runs matched
# shared decisions=True: 100.0% of 1,000 runs matched
```

A toy we ran in the sandbox: three parallel workers, three style choices. Without a shared decision, they agree **only by luck**. Real agents guess less randomly, but the failure is the same.

**Gotchas:** give each subagent an **objective, an output format, tools and clear boundaries** (Anthropic's checklist). **Scale effort to the task**: Anthropic's early version spawned 50 subagents for simple questions. And start with **one agent**; split only when you need different tools, rules or a clean context.
</div>

## Top story 1 · Inside ARTEX, the hacking tool run by agent teams

<span class="tag hot">BIG DEAL</span><span class="tag dev">DEV</span><span class="tag watch">SECURITY</span>

**What happened.** Microsoft published a detailed guide to **ARTEX**, an "AI autonomous penetration testing system" now used by **six state-linked and criminal groups**, including Salt Typhoon, Crystal Typhoon and North Korea-linked Onyx Sleet and Pearl Sleet. We've covered ARTEX attacks before; this is the first look at **how it works inside**. [(Microsoft)](https://www.microsoft.com/en-us/security/blog/2026/11/25/what-defenders-need-to-know-artex-agentic-ai-framework-threat-actors-abuse/)

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Origin:** a GitHub user published it as open source in **July 2026**. The original source was removed in October, but **forks remain**. In November, Chinese firm ThreatBook claimed it and began selling **"ARTEX Pro"**.
- **Any model works.** Operators can plug in frontier, open-weight or safety-stripped models. A **"pool" switches providers** when a key fails or hits a rate limit, so one campaign can span many accounts.
- **Machine-speed volume:** in one Storm-0940 campaign, Microsoft logged **more than 151,000 failed sign-ins**, peaking at **2,900 a minute**.
- **The counter-move is deception.** Honeypots and decoys give agents worthless targets, **tarpits burn their time and budget**, and "fake wins" make them stop on a false success.

**Why it matters.** The coordinator pattern from Part 1 is now **off-the-shelf attack tooling**. That shifts defence from "spot the hacker" to "waste the agent's budget", because an agent will **chase every shiny decoy** a human would ignore.
