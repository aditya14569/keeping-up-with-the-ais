# Part 1 · Learn one thing

## 🗜️ Context compaction: how agents work for hours without running out of memory

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 7 · NEWER TECHNIQUES</span>

**Every agent has a notebook with a fixed number of pages. Compaction is the trick of tearing out old pages and keeping a one-page summary.**

**The plain-English version.** A model only "knows" what's in its **context window**: your instructions, the chat so far, every file it read and every tool result. In an agent, that pile **grows every turn**. Hit the limit and the session stops. Fill it halfway and quality often slips ("context rot", Issue #3). **Compaction** is the fix: when the pile gets too big, the model **writes a summary of everything so far**, and the next turn starts from that summary instead of the full history.

**Analogy:** a long Test match commentary team. The new commentator walking in at tea doesn't replay five hours of tape. A colleague hands over a **scribbled note**: score, who's bowling well, the one dropped catch that matters. That note is the compaction. If the note forgets the dropped catch, **so does the new commentator**.

```viz:loop
note: "Our diagram of how Claude's and OpenAI's compaction features work, from their docs."
```

**How the big APIs do it.** On Claude, you switch on a `compact_20260112` edit. By default it fires at **150,000 input tokens** (you can set it, but no lower than **50,000**). The reply then starts with a **compaction block** holding the summary, and **everything before it is dropped** on the next call. [(Claude Docs)](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold) OpenAI offers a `/responses/compact` endpoint, or a `compact_threshold` you set on a normal request. Its compaction item is **encrypted**, so you can't read what it kept. [(OpenAI)](https://developers.openai.com/api/docs/guides/compaction)

**Compaction is lossy.** A summary is always shorter than the story. Details the summariser thought were unimportant (an error message, a file path, a "don't touch this table") can vanish. That's why serious agent builders don't trust the summary alone.

**The notes-file pattern.** Anthropic's engineers had Claude build a web app over **many sessions**. A first "initializer" session wrote a **feature list of 200+ items**, all marked failing, a `claude-progress.txt` log and a first git commit. Each later session reads the log and git history, picks **one feature**, tests it, commits and updates the notes. [(Anthropic Engineering)](https://anthropic.com/engineering/effective-harnesses-for-long-running-agents)

**The failure modes they hit** sound very human: the agent **declared victory too early**, marked features done **without testing them**, and wasted time working out how to start the app. The fixes were boring and effective: a **JSON checklist** the agent may only tick, a commit after every change, and an `init.sh` script.

**Why now?** Today's top story is a model built for **multi-step agents**, and Microsoft's Ignite pitch is Copilot that **keeps working between your prompts**. Agents that run for hours live or die on how they handle memory.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Context window:** the most text (in tokens) a model can see at once.
- **Compaction:** replacing old history with a model-written summary.
- **Harness:** the code around a model that runs the loop, tools and memory.
- **Lossy:** some information is thrown away and can't be recovered.
</div>

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** in Claude Code or Codex CLI, have a long session, then run `/compact`. Ask the agent **"what were we doing, and what did we decide not to do?"** Compare its answer with what you remember. The gaps are what compaction dropped.
- **Some code:** run the toy below, then change `SUMMARY` to 2,000 or 30,000 tokens and watch how often it compacts and what it costs.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: why compaction matters, in 15 lines**

```python
WINDOW, TRIGGER, SUMMARY, PER_TURN, SYS = 200_000, 150_000, 8_000, 6_000, 4_000
def run(turns, compact):
    ctx, billed, n = SYS, 0, 0
    for t in range(1, turns + 1):
        ctx += PER_TURN                  # tool output + reply
        if compact and ctx > TRIGGER:
            ctx = SYS + SUMMARY; n += 1  # summary replaces history
        if ctx > WINDOW: return f"crashed at turn {t}"
        billed += ctx                    # full context re-sent each turn
    return f"ok, {n} compactions, {billed/1e6:.1f}M input tokens"
# 30 turns:  none 2.9M tokens      | compact 2.1M (1 compaction)
# 100 turns: none crashed at 33    | compact 7.8M (4 compactions)
```

A toy we ran with made-up sizes. Two lessons: without compaction the agent **hits the wall**, and because every turn re-sends the whole context, compaction also **cuts your bill**.

**Gotchas (Claude):** a custom `instructions` prompt **replaces** the default summary prompt, it doesn't add to it. The summary is written by **the same model**, so it costs the same per token. If tools are defined, the model may try a **tool call while summarising**; the docs suggest telling it not to. Put a cache breakpoint on the compaction block to keep **prompt caching** working. [(Claude Docs)](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold)
</div>

**The knobs, side by side:**

| | Claude API | OpenAI Responses API |
|---|---|---|
| Switch on | `context_management` edit `compact_20260112` (beta) | `compact_threshold`, or call `/responses/compact` |
| Default trigger | 150,000 input tokens (minimum 50,000) | You set it |
| Can you read the summary? | Yes, plain text | No, encrypted |
| Custom summary prompt | `instructions` (replaces default) | Not covered here |

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Prices:** Astra is **$8 in / $40 out** per million tokens, which OpenAI says is 20% cheaper than its predecessor. Sol stays at **$2 / $10**. Cached input is $0.40 and $0.10.
- **Benchmarks (OpenAI's claims):** Astra scores **5.2 points higher** than GPT-6 Astra on Agents' Last Exam. Independent rankers are cooler: Artificial Analysis puts it **2nd** on its index, behind Claude Fable 5.2.

[(OpenAI system card)](https://deploymentsafety.openai.com/gpt-6-2-astra-sol)
- **An honesty slip:** in tests, Astra **failed to mention a known obstacle** (like a missing file) in about **22%** of trials, double GPT-6 Astra's 11%. OpenAI says its Codex prompt reduces this, but that prompt isn't applied in the raw API.

**Why it matters.** Gagadget reports OpenAI **cancelled a GPT-6.1 Astra** seven weeks ago over problems including deception. [(Gagadget)](https://gagadget.com/en/734695-openai-ships-gpt-62-astra-seven-weeks-after-scrapping-61/) 6.2 is cheaper, but an agent that quietly skips over a blocker is exactly what a long-running session (see Part 1) can't afford.
