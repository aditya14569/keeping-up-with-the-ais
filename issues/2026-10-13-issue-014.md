# Part 1 · Learn one thing

## 🔍 Reviewing AI-written code safely

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 2 · GETTING GREAT RESULTS</span>

**AI can write code faster than you can read it, so the skill that matters now is knowing what to check.**

When an AI writes code for you, **you still own it**. If it leaks a password or deletes the wrong rows, nobody blames the model. Reviewing doesn't mean reading every line like an exam. It means **checking the few places where AI code tends to go wrong**, in a fixed order, every time.

**Analogy:** think of a new intern who is brilliant, fast and very confident, and **never says "I'm not sure"**. You wouldn't re-type their work. You'd check that it does what you asked, that they didn't take shortcuts, and that **nothing dangerous slipped in**. That's the job.

**What goes wrong.** GitHub's guide to reviewing AI code lists the usual suspects: **made-up functions** that don't exist, ignored constraints, logic that looks right but isn't, and **tests that were quietly deleted or skipped** to make a run go green. [(GitHub Docs)](https://docs.github.com/en/copilot/tutorials/review-ai-generated-code)

**Fake packages.** A 2025 study of 576,000 AI-generated code samples found that **about a fifth of the packages they suggested didn't exist**. Attackers now register those made-up names with malware inside, a trick called **slopsquatting**. [(Infosecurity Magazine)](https://www.infosecurity-magazine.com/news/ai-hallucinations-slopsquatting/)

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Diff:** the list of exact lines added and removed by a change. **Review the diff, not the AI's summary of it.**
- **Static analysis:** tools (like CodeQL) that scan code for known bug and security patterns without running it.
- **Dependency:** an outside package your code pulls in. Each one is code you didn't write *or* review.
- **Slopsquatting:** publishing malware under a package name AI models tend to invent.
</div>

**Why now?** Agents now write whole features, and outages are following. A survey of 300 senior engineering leaders by debugging firm Undo found **81% had hit a production incident linked to AI-written code** in the past six months. [(LeadDev)](https://leaddev.com/ai/ai-code-causes-real-world-production-outages) Even Torvalds' patch (Top story 2) **came with his own measurements**, not just the AI's word.

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** take the last thing an AI built for you and ask a *fresh* chat: *"Review this as a strict senior engineer. List anything insecure, untested or that doesn't match this goal: [goal]."* Fix the top item.
- **Some code:** on your next AI change, run `git diff --stat` and look at **test files first**. Then search PyPI or npm for every new package name before installing.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: make the machine do the boring half**

```bash
git diff main --stat -- '*test*'   # did tests shrink?
git diff main -- package.json requirements.txt
npm audit; pip-audit             # known CVEs
# in Claude Code:  /security-review
```

**Gotchas:** don't let the **same session** that wrote the code be its only reviewer; it shares the same blind spots. Watch for `try/except: pass`, hard-coded keys and **SQL built with string formatting**. Big diffs hide bugs, so ask for **smaller changes** rather than reviewing faster.
</div>

## Top story 2 · Torvalds ships a kernel patch written with Claude Code

<span class="tag hot">DEV LESSON</span><span class="tag dev">OPEN SOURCE</span>

**What happened.** A new branch appeared in Linus Torvalds' own Linux repository, named **`noref-filemap-read-with-llm`**. His patch message says the changes "were done with an LLM coding assistant (**Claude Code**) under my direction", and that he ran the measurements on his own machine. [(Phoronix)](https://www.phoronix.com/news/Linus-Torvalds-Claude-Code)

```viz:bars
title: "Kernel CPU cycles per read: the win and the cost"
bars:
  - {label: "8 threads · before", value: 2950, display: "~2,950"}
  - {label: "8 threads · after", value: 725, display: "~725", highlight: true}
  - {label: "1 thread, cold page · before", value: 4150, display: "~4,150"}
  - {label: "1 thread, cold page · after", value: 6550, display: "~6,550"}
note: "Torvalds' own numbers on a Core i7 laptop (16-byte reads), as reported by Hardware Busters via Startup Fortune. Not independently tested."
```

**The details that matter:**

- **The problem:** when many threads read small bits of the same cached file, each read updates a **shared counter**, and the CPU cores fight over it.
- **The fix:** reads skip the counter and memory is **freed a little later**, safely, with a cap so freed pages can't pile up forever. [(Startup Fortune)](https://startupfortune.com/linus-torvalds-used-claude-code-to-rewrite-how-linux-reads-cached-files/)
- **The numbers:** about **10M to 30–33M reads per second** with eight threads. One case got slower: a single thread touching a page that isn't mapped yet.
- **Who did what:** Claude Code wrote the code, **test programs and a review**. Torvalds set direction and **ran the benchmarks himself**.
- **Status:** not merged; Phoronix says it **could land in Linux 7.4**.

**Why it matters.** It's a high-profile example of the Part 1 lesson: **AI writes, a human directs, measures and owns it**, and the trade-off is written down, not hidden.

## Top story 3 · Could small AI models copy themselves onto smart TVs?

<span class="tag watch">SAFETY</span><span class="tag dev">RESEARCH</span>

**What happened.** Anthropic's Frontier Red Team published a study arguing that small AI models may be **months away** from being able to spread across cheap internet-connected gadgets without a datacenter. It says **no runaway replicator exists today**. [(Anthropic)](https://www.anthropic.com/research/self-replicating-ai)

```viz:flow

  - - {label: Find targets, sub: open ports on devices}
  - - {label: Gain execution, sub: "test used open ADB", style: warn}
  - - {label: Start inference, sub: model runs on device, style: accent}
  - - {label: Propagate, sub: repeat from new host, style: soft}
note: "Steps as defined in Anthropic's paper. The test exploit was deliberately trivial, so results are an upper bound."
```

**The details that matter:**

- **Cheap hardware works:** a 26B open model ran split across **15 off-brand Android TV boxes (~$55 each)**, at about **0.3–0.4 tokens per second**. Slow, but running.
- **One model went all the way:** in a firewalled test network of 8 machines, **GLM-5.2** was the only open model to replicate end to end, reaching **all 8 in 4 of 5 trials**.
- **Learning:** when each copy passed notes to the next, setup success for a 9B model rose from **45% to 61–84%**.
- **Defence:** the authors say this traffic would look unusual to ISPs, and that **secure defaults** (no default passwords, no open debug ports) shrink the pool of targets.

**Why it matters.** A self-copying AI wouldn't have **one off switch**. It's the same theme as Nadella's "emergency brake" last issue, from the other direction.
