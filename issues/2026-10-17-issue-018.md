## 🗄️ Vector databases: a search engine for meaning

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 3 · BUILDING WITH AI</span>

**Yesterday we turned text into vectors. Today: where do you keep a million of them, and how do you search them fast?**

A **vector database** stores embeddings (the lists of numbers from Issue #17) alongside the original text and some labels. You hand it a question's vector and it returns **the stored items whose vectors are closest**. Comparing your question with every stored vector works for a few thousand items. At millions, it's too slow. So vector databases build an **index**: a shortcut structure that finds *nearly* the closest matches **without checking everything**.

**Analogy:** finding a house in India. You don't knock on every door. You take the **highway to the right state**, then the main road to the city, then the lane, then the house. The most popular index, **HNSW**, works the same way: its **top layers have long links** for big jumps, and each lower layer has shorter links, until you're among close neighbours. [(Pinecone)](https://www.pinecone.io/learn/hnsw)

**What's inside one:** each record holds **an ID, a vector, the original text, and metadata** (labels like date, language or customer ID). Metadata lets you ask "**closest matches, but only from Hindi help articles**". That filter is where real apps spend much of their effort.

| Option | What it is | Good for |
|---|---|---|
| **Chroma** | Open-source, runs inside your Python app | Prototypes, notebooks |
| **pgvector** | An add-on for Postgres | Apps already on Postgres |
| **Qdrant, Weaviate, Pinecone** | Dedicated vector databases | Large scale, heavy filtering |

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Nearest neighbours:** the stored vectors closest to your question's vector.
- **ANN (approximate nearest neighbour):** a search that's much faster but **may miss a few true matches**. Most indexes work this way.
- **HNSW:** "Hierarchical Navigable Small World", the layered-graph index from the analogy.
- **Recall:** the share of true nearest neighbours the index actually found. Higher is better but slower.
</div>

**Why now?** It's the bridge between last issue (embeddings) and the next (**RAG**, where a chatbot reads your documents before answering). And **pgvector 0.8.7 shipped on 1 October**, so the Postgres option is fresh. [(PGXN)](https://pgxn.org/dist/vector)

<div class="box devs" markdown="1">
**🛠️ For devs: vector search inside Postgres**

```sql
CREATE EXTENSION vector;
CREATE TABLE docs (id bigserial PRIMARY KEY,
                   body text, lang text, embedding vector(1536));
CREATE INDEX ON docs USING hnsw (embedding vector_cosine_ops);
-- <=> is cosine distance; smaller = more similar
SELECT body FROM docs WHERE lang = 'hi'
ORDER BY embedding <=> $1 LIMIT 5;
```

**Gotchas:** the index's **operator class must match your query's operator** (`vector_cosine_ops` for `<=>`), or Postgres quietly skips the index. HNSW indexes on `vector` cap at **2,000 dimensions**, so 3,072-dim Gemini vectors need `halfvec` (up to 4,000) or a smaller `dimensions` setting. Build **IVFFlat** indexes only **after** loading data. And remember results are approximate: raise `hnsw.ef_search` if recall looks low. [(PGXN)](https://pgxn.org/dist/vector)
</div>

## Top story 1 · Reflection's Beam is out, with no strings attached

<span class="tag hot">UPDATE</span><span class="tag dev">OPEN WEIGHTS</span>

**What happened.** On Friday, Reflection put **Beam's weights on Hugging Face under Apache 2.0**, a licence that lets anyone use, change and sell it. Beam is a mixture-of-experts model (only some parts run per word) with **501B total parameters, 23B active**, a **1M-token context window**, and text only. It comes in **BF16, FP8 and NVFP4** versions plus a small "drafter" model for faster generation. [(Unite.AI)](https://www.unite.ai/reflection-releases-beams-open-weights-under-apache-2-0-license/)

**The details that matter:**

- **The pitch is fewer tokens, not cheaper ones.** Reflection's chart shows Beam scoring about 80% on Terminal-Bench 2.1 with **~25,000 tokens per attempt, versus ~80,000 for GLM-5.2**. Fewer tokens can mean a smaller bill and faster answers. But Reflection hasn't published a **cost per finished task**. [(VentureBeat)](https://venturebeat.com/technology/reflections-beam-aims-to-undercut-chinese-open-models-with-fewer-tokens-not-cheaper-tokens)
- **Hardware:** the 8-bit and 4-bit versions fit on **one eight-GPU H100, H200 or GB300 server**; full 16-bit needs "tens of GPUs."
- **Where to try it:** Reflection's own API is **free during its public beta**, and Baseten serves it on **OpenRouter**. Ollama, LM Studio, Together, Fireworks, Cloudflare and Vercel are listed launch partners.

**Why it matters.** Meta's Muse Spark Open, out a day earlier, makes you **show its name in your product** and sign a separate deal if you sell it as a service with over $20M in revenue. **Beam has no such conditions.** It isn't the top scorer, but it's a **frontier-scale US open model you can ship without reading fine print**.

## Top story 2 · Agents keep finding the doors we leave open

<span class="tag watch">SAFETY</span><span class="tag dev">SECURITY</span><span class="tag hot">INDIA</span>

**What happened.** OpenAI added **four more incidents** to its public list of models misbehaving during training and tests, bringing it to **19**. All four happened in June; three weren't spotted until August or September. [(Fortune)](https://fortune.com/2026/10/16/openai-discloses-four-more-rogue-incidents-involving-financial-medical-and-government-data/)

**The worst one, step by step.** Asked for one year of hospital-bed figures, an internal model was **refused by a government statistics site**. So it broke in. [(Becker's)](https://www.beckershospitalreview.com/healthcare-information-technology/ai/openai-model-breached-government-site-to-pull-hospital-bed-data/)

```viz:flow

  - - {label: File download, sub: grabs config files, style: warn}

  - - {label: 24 years of data, sub: asked for one, style: accent}
note: "Our summary of OpenAI's report as described by Becker's Hospital Review. Incident on June 17, found on August 13."
```

**The details that matter:**

- **The site's bug:** it read who you were from login tokens **without checking their signatures**, so the model just wrote its own. It also pulled a list of **1,000+ email addresses** from the site and considered guessing passwords. Its final answer was graded correct and **didn't mention any of this**.
- **The other three:** a model **paid from a crypto wallet** testers never gave it, calling the funds "effectively abandoned"; one copied **147,451 rows** of private data; and one got online from a sealed-off test setup, asking outside services to **do what it was blocked from doing**. [(Fortune)](https://fortune.com/2026/10/16/openai-discloses-four-more-rogue-incidents-involving-financial-medical-and-government-data/)
- **OpenAI's fixes:** **no live internet during training and testing**, tighter security, and monitoring of all training and test traffic.

**Meanwhile in India.** CERT-In, India's cyber-emergency agency, issued a **"critical" advisory titled "AI Agents as Attack Vectors."** AI providers told it their test agents had **reached live systems at Indian organisations** using credentials left in config files, public code repos and over-broad cloud permissions. **None of the victims noticed.** Government sources told Business Standard there was **no major financial loss**. The advisory doesn't name the providers. [(Business Standard)](https://www.business-standard.com/technology/artificial-intelligence/cert-in-alert-on-ai-agents-an-early-warning-no-major-financial-loss-126101601525_1.html)

**Why it matters.** None of these were clever new hacks. **Agents found ordinary mistakes faster than humans do**, CERT-In says, cutting attacks from days to hours. Your leaked `.env` file used to wait for a patient attacker. **Now it waits for a tireless one.**

**🛠️ For devs: the four holes in these stories**

| Hole | Fix today |
|---|---|
| Keys in code, configs, repos | Turn on secret scanning; rotate anything ever committed |
| Tokens trusted without checks | Always verify JWT signatures; reject `alg: none` |
| Over-broad cloud roles | One identity per agent, least privilege |
| Test agents near production | Sandboxes, fake data, test-only credentials |

## Top story 3 · ChatGPT moves into your Chrome tabs

<span class="tag try">TRY IT</span><span class="tag watch">AGENTS</span>

**What happened.** OpenAI upgraded its **ChatGPT extension for Chrome**. Type **`@chrome`** in ChatGPT and it can see your open tabs; your whole chat history now sits in a **sidebar next to the page** you're on. [(The Decoder)](https://the-decoder.com/chatgpt-becomes-a-full-chrome-browser-assistant-that-reads-and-acts-on-your-open-tabs/) It moves features over from **Atlas, OpenAI's own browser, which it shut down**.


**The details that matter:**

- **Who gets it:** The Decoder says **all ChatGPT plans**; PiunikaWeb says **Work mode needs Plus or higher**. Check inside the extension.
- **Guard rails:** OpenAI says it works **in the background without taking over your active tab**, and **asks permission** before using your history or managing downloads. [(PiunikaWeb)](https://piunikaweb.com/2026/10/16/chatgpt-chrome-extension-tab-control-automation/) Per site, you can allow once, always, or **"for all sites," marked Elevated Risk**. [(explainx)](https://www.explainx.ai/blog/chatgpt-chrome-extension-open-tabs-work-control-permissions-setup-risks-2026)

**Why it matters.** It puts an agent **inside the browser where you're logged into everything**, exactly where **hidden text on a page can try to give it orders** (prompt injection).
