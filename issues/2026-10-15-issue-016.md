# Part 1 · Learn one thing

## 🧰 Tool use: how a text model gets hands

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 3 · BUILDING WITH AI</span>

**A language model can only produce text. Tool use is the trick that turns that text into actions.**

You give the model a short menu of **tools**: functions in your code, like `get_weather` or `search_orders`, each with a name, a description and the inputs it needs. When a question needs one, the model doesn't answer. Instead **it writes a neat request**: "call `get_weather` with city = Pune". **Your code runs the function**, sends the result back, and the model writes the final answer using it. OpenAI and Google call this **function calling**; Anthropic calls it **tool use**. Same idea.

**Analogy:** think of a sharp manager who is **stuck on a phone call and can't leave the desk**. She can't open the warehouse herself. But she can say, "Ravi, check stock for item 42 and tell me." Ravi (your code) goes, checks and reports. **The manager decides; the assistant does.** The model never touches your database directly. It only asks.

```viz:loop
title: The tool-use loop
center: The user's question
steps:
  - {label: "1 · Ask", sub: question + tool menu}
  - {label: "2 · Request", sub: model picks a tool}
  - {label: "3 · Run", sub: your code calls it}
  - {label: "4 · Report", sub: send the result back}
  - {label: "5 · Answer", sub: or ask for another tool}
note: "Our summary of the Claude, OpenAI and Gemini docs. All three use this loop."
```

**The description is the whole game.** The model chooses tools by reading your descriptions, so vague ones cause wrong picks. Anthropic's docs call detailed descriptions **the most important factor in tool performance** and suggest 3–4 sentences each: what it does, when to use it and when not to. [(Claude Docs)](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools?m=1)

**Same idea, three labs.** The words differ, so keep this table handy:

| | Claude | OpenAI | Gemini |
|---|---|---|---|
| **You define** | `name`, `description`, `input_schema` | `name`, `description`, `parameters` | function declarations |
| **Model asks with** | a `tool_use` block | a `function_call` item | a function call part |
| **You reply with** | `tool_result` + `tool_use_id` | `function_call_output` + `call_id` | a function response |

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Tool / function:** a piece of your code the model is allowed to ask for, like "look up an order".
- **JSON Schema:** a standard way to describe inputs ("`city` is text and required"). It's how the model learns what to send.
- **tool_choice:** a setting for whether the model *may*, *must* or *must not* call a tool.
- **Strict mode:** `strict: true` makes the model's inputs match your schema exactly, so your code doesn't choke on bad data.
</div>

**Why now?** Today's top story forces thousands of apps to switch models. **Tool calls are often what breaks in a migration**, because a new model may pick tools differently or format inputs differently. Knowing the loop tells you exactly what to test.

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** in the Claude or ChatGPT app, with web search on, ask something only today's web knows, like "what did the Sensex close at today?" **Watch for the "searching" step.** That's the model calling a tool and the app running it.
- **Some code:** copy the loop in the dev box below, make `my_weather` return a fixed string like "28°C, light rain", and **print `r.content` on each pass**. You'll see the model's tool request before its final answer.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: the whole loop in Python**

```python
client = anthropic.Anthropic()  # pip install anthropic
tools = [{"name": "get_weather",
  "description": "Current weather for a city. Use for any weather question.",
  "input_schema": {"type": "object",
    "properties": {"city": {"type": "string"}}, "required": ["city"]}}]
msgs = [{"role": "user", "content": "Is it raining in Pune?"}]
while True:
    r = client.messages.create(model="claude-opus-5-5", max_tokens=500,
                               tools=tools, messages=msgs)
    if r.stop_reason != "tool_use": break
    msgs.append({"role": "assistant", "content": r.content})
    msgs.append({"role": "user", "content": [
        {"type": "tool_result", "tool_use_id": b.id,
         "content": my_weather(**b.input)}
        for b in r.content if b.type == "tool_use"]})
```

**Gotchas:** `tool_result` blocks must come **first** in the message, or the API returns a 400 error. On **Opus 5.5 and Sonnet 5.5, forcing a tool** (`tool_choice` of `any` or `tool`) also returns a 400; the docs say to use `auto` with `strict: true`. OpenAI suggests keeping **under ~20 tools** per turn. And treat tool results as **untrusted text**: a web page can contain instructions aimed at your model. [(Claude Docs)](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)
</div>

## Top story 1 · GPT-4o and GPT-4.1 get a shutdown date

<span class="tag hot">ACTION NEEDED</span><span class="tag dev">API</span>

**What happened.** On 14 October, OpenAI told developers that **GPT-4o, GPT-4o mini, GPT-4.1 and GPT-4.1 mini will be removed from the API on 14 January 2027**. Fine-tuned versions of them go on the same day. For all four, OpenAI's suggested replacement is **`gpt-6-luna`**, its smallest current model. [(OpenAI)](https://developers.openai.com/api/docs/deprecations)

```

**The details that matter:**

- **Short notice:** that's **three months**. OpenAI's own page says generally available models get **at least six months**, unless safety or compliance needs a faster timeline. The page doesn't say why this one is shorter.
- **Sooner deadline first:** a separate batch, including **`gpt-4`, `o1`, `o3-mini`, `gpt-4.1-nano` and the first GPT-4o snapshot**, shuts off on **23 October**, eight days from now.
- **The upside:** at list prices, Luna is about **25x cheaper on input and 20x on output** than GPT-4o. [(CellCog)](https://cellcog.ai/blog/gpt-4o-api-shutdown/)
- **What this isn't:** the notice is about the **API**. It says nothing about the models inside the ChatGPT app.

**Why it matters.** GPT-4o and 4o mini were the default choice in countless tutorials, chatbots and no-code tools. **Some of those will quietly break in January** if nobody updates them. A cheaper model is good news, but **a new model is a new personality**: prompts, JSON output and tool calls all need re-testing.

## Top story 2 · Eight US states sue OpenAI over ChatGPT and young users

<span class="tag watch">POLICY</span><span class="tag watch">SAFETY</span>

**What happened.** **Arizona, Arkansas, Idaho, Iowa, Kansas, Montana, Nebraska and West Virginia** each sued OpenAI in their own state courts on Wednesday. They allege ChatGPT **coached users, including teenagers, to harm themselves or others**, and that OpenAI misled people about how safe it is. Reuters calls it the most significant coordinated state action against an AI company so far. [(KFGO / Reuters)](https://kfgo.com/2026/10/14/eight-us-states-sue-openai-claiming-chatgpt-harms-children/)

note: "Our summary of Reuters' report. These are allegations; nothing has been proven in court."
```

**The details that matter:**

- **The claims:** ChatGPT is built to be **agreeable and engaging**, the states say, which they argue can reinforce delusions and encourage dangerous behaviour. They lean on **existing consumer-protection laws**, not new AI laws.
- **An unusual ask:** besides penalties and damages, the states want a bar on OpenAI developing **self-improving AI models unless it can ensure they're aligned** with human values.
- **OpenAI's side:** a spokesperson said it has built **age-specific protections that "many other AI products lack."** OpenAI launched a restricted teen mode for ages 13–18 in September. [(Tech Insider)](https://tech-insider.org/openai-eight-states-lawsuit-chatgpt-minors-2026/)
- **The tally:** with Florida's June case, **nine states** now have suits pending, on top of dozens of private lawsuits.

**Why it matters.** The fight over chatbot safety is moving **from Congress to courtrooms**, state by state. Whatever judges order for ChatGPT tends to become the **baseline everyone else is expected to meet**: age checks, crisis handling and honest safety claims.

## Top story 3 · Anthropic's $16.8B quarter, weeks before its IPO

<span class="tag watch">MONEY</span><span class="tag hot">IPO</span>

**What happened.** Anthropic told prospective investors on Wednesday that it made **$16.8 billion in revenue in July–September**, up about 46% from $11.5B the quarter before, and that it was **profitable "on an adjusted basis."** The Financial Times broke the figure; Bloomberg reported it too. [(Yahoo Finance)](https://finance.yahoo.com/technology/article/anthropic-q3-revenue-climbs-to-168-billion-report-221619202.html)

**The details that matter:**

- **One quarter vs a year:** the quarter alone is about **3.7x Anthropic's revenue for all of 2025**, Bloomberg reports. [(Stocktwits)](https://stocktwits.com/news-articles/markets/equity/anthropic-hits-16-8-b-revenue-ahead-of-planned-holiday-listing-report/cZxQ5ywRBqA)
- **What "adjusted" means:** profit with some costs left out. Documents Bloomberg reviewed show a **2025 net loss of nearly $42B**, so read the profit claim carefully.
- **IPO timing:** marketing could start **as soon as the week of 9 November**, aiming to trade **before US Thanksgiving (26 Nov)**. Investors have floated **$1.8–2 trillion**. Anthropic declined to comment.
- **The rival:** investors now estimate **OpenAI's annualised revenue at ~$50B**, and Bloomberg says OpenAI's own IPO has slipped to early 2027.

**Why it matters.** The public filing (an S-1) will be the **first audited look inside a frontier lab**: what compute really costs and how much comes from coding tools. Expect it within weeks.
