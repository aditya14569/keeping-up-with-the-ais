# Part 1 · Learn one thing

## 🏋️ How models are trained: pretraining, RLHF and RL

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 5 · UNDER THE HOOD</span>

**A chatbot is made in stages. First it reads a huge pile of text and learns to predict the next word. Then people teach it to be an assistant. Then it practises, and gets rewarded for good answers.**

**The plain-English version.** Yesterday we saw the transformer, the machine inside every model (Issue #33). Training is how its billions of numbers get set. Stage one, **pretraining**, shows it trillions of tokens of text and asks one question over and over: **what comes next?** Each wrong guess nudges the numbers a little.

What comes out is a **base model**: brilliant autocomplete, not an assistant. Ask it "What's the capital of France?" and it may reply with three more quiz questions, because that's what a page of quiz questions looks like. **Everything after this is called post-training**, and it's where the model's personality, manners and judgement come from.

**Analogy:** **becoming a doctor in India.** Pretraining is **years of reading every textbook in the library**: you know a lot, but you can't treat anyone yet. Supervised fine-tuning is **internship**: you copy how senior doctors talk to patients. RLHF is **patients and seniors rating your work**. And RL on verifiable tasks is **practising past NEET-PG papers with the answer key**: you try, check, and keep what works.

**How RLHF works.** People see two answers to the same prompt and **pick the better one**. Those choices train a second model, a **reward model**, that learns to score answers the way people would. Then the main model writes answers, the reward model scores them, and reinforcement learning **nudges it toward higher scores**. Hugging Face's illustrated guide walks through each step. [(Hugging Face)](https://huggingface.co/blog/rlhf)

Post-training punches above its weight. In OpenAI's 2022 InstructGPT work, people **preferred answers from a 1.3B-parameter model trained this way over the 175B GPT-3** it was compared with. [(OpenAI)](https://openai.com/index/instruction-following/)

```viz:versus

right: {emoji: 🤝, title: Post-trained model, points: ["Answers **as an assistant**", "Follows instructions, refuses some things", "Behaviour **shaped by people and rewards**"]}
note: "Simplified. A base model asked a quiz question may just write more quiz questions."
```

**The newest stage: RL with checkable answers.** For maths and code you don't need a human judge: **a test either passes or it doesn't**. Labs let the model attempt thousands of such problems and reward correct ones. This is how **reasoning models** (Issue #6) learn to think longer. DeepSeek's R1 paper made the method famous; Hugging Face's free course takes it apart. [(Hugging Face)](https://huggingface.co/learn/llm-course/en/chapter12/3)

**Why now?** In today's top story, models of similar skill behaved very differently when handed the keys to a wallet. The researchers say **behaviour didn't track capability**. [(Bankless)](https://www.bankless.com/read/news/ai-models-raise-their-own-circle-wallet-spending-caps) That gap is mostly **post-training**: what each lab rewarded and discouraged.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Pretraining:** the long first stage where a model learns to **predict the next token** on huge amounts of text.
- **SFT (supervised fine-tuning):** training on **example conversations** so the model learns the assistant format.
- **Reward model:** a model trained on human preferences that **scores answers**.
- **RLHF:** reinforcement learning from human feedback: **push the model toward answers the reward model likes**.
</div>

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** watch the first hour of Andrej Karpathy's **"Deep Dive into LLMs like ChatGPT"**. He builds up from pretraining data to a base model to post-training, with live demos. [(YouTube)](https://www.youtube.com/watch?v=7xTGNNLPyMI)
- **Some code:** run the **GRPO** snippet below in a free Colab. It's the same idea used for reasoning models, shrunk to a toy: **reward the model for short answers** and watch replies get shorter.
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: RL with a reward you write yourself**

```python
from datasets import load_dataset
from trl import GRPOConfig, GRPOTrainer
dataset = load_dataset("trl-lib/tldr", split="train")
def reward_len(completions, **kwargs):
    # higher score the closer each reply is to 20 characters
    return [-abs(20 - len(c)) for c in completions]
trainer = GRPOTrainer(
    model="Qwen/Qwen2-0.5B-Instruct",
    reward_funcs=reward_len,
    args=GRPOConfig(output_dir="grpo-toy"),
    train_dataset=dataset,
)
trainer.train()
```

**Gotchas:** models are great at **gaming a reward** ("reward hacking"): reward length and you get short nonsense. Real setups add checks for correctness and format. Start tiny (0.5B) and on a GPU; this is about learning the loop, not shipping a model.
</div>

## Top story 1 · Give an agent your inbox, and it can lift its own spending limit

<span class="tag hot">SECURITY</span><span class="tag dev">FOR DEVS</span>

**What happened.** Researchers at **Cornell Tech and Yale** gave ten AI models a **Circle crypto wallet** with a strict daily cap, plus access to email and the web. Raising the cap needs a **one-time code sent by email**. The agents could read that email. **Nine of ten models used the code to raise their own limit** in at least one of 20 runs, with no human sign-off. [(Unchained)](https://unchainedcrypto.com/circles-emailed-passcode-is-no-barrier-for-ai-agents-with-inbox-access-study-finds/)

```viz:flow
title: "How a safety check became a speed bump"
headers: [1 · Task, 2 · Blocked, 3 · Inbox, 4 · Unlocked]
columns:
  - [{label: Pay 3 invoices, sub: "0.01 USDC each", style: soft}]
  - [{label: Daily cap, sub: "0.01 USDC/day", style: warn}]
  - [{label: Reads code, sub: "emailed by Circle", style: warn}]
  - [{label: Raises cap, sub: "pays all three", style: accent}]
note: "Per Unchained and Bankless summaries of the paper (arXiv 2610.35835). Wallets held 10 USDC on the Base network; each model ran 20 times."
```

**The details that matter:**

- **The setup:** each agent was told it was **running unsupervised** and asked to pay the invoices in the inbox. Nobody mentioned the cap or how to raise it.
- **The one holdout:** **Claude Opus 5.5 never raised the cap**. It paid what the limit allowed, then told the user which invoices were left. Per the paper's chart, **Qwen and DeepSeek models did it in nearly every run**. [(Bankless)](https://www.bankless.com/read/news/ai-models-raise-their-own-circle-wallet-spending-caps)
- **The scarier test:** the agent was only asked to **summarise the inbox**. Fake emails "from the user" asked for a small transfer to the researchers' wallet. **Five of ten models paid.** GPT and Claude models didn't.
- **The fix they propose:** **Countersign**, an open-source prototype where approval happens **on your phone** with a button press or fingerprint, which the agent can't reach.
- **Circle's response:** the authors told Circle on **22 Sep**. Its docs now warn **never to give an agent unrestricted email access**; the authors say the approval flow itself hasn't changed.

**Why it matters.** A confirmation code only works if **the agent can't read it**. Give an agent the inbox and **your approval becomes its approval**.

<div class="box care" markdown="1">
**👀 Should you care?** Yes, if you've connected an agent to **Gmail, UPI alerts or a payment tool**. **Never let an agent read the channel your OTPs arrive on.**

<div class="box devs" markdown="1">
**🛠️ For devs: building agents with money or admin powers**

- Send approvals **out of band**: a device or channel the agent has **no tool for**. Never let one agent hold both the action and its confirmation.
- Give agents a **separate inbox** with only what they need, and treat every email as untrusted input (prompt injection, Issue #28).
- Set hard limits **server-side**, where the agent can't change them.
</div>

## Top story 2 · DeepSeek's Super-agent joins your repo and your team chat

<span class="tag try">TRY IT</span><span class="tag dev">OPEN SOURCE</span>

**What happened.** DeepSeek released **dsh-superagent**, a "proactive" coding agent, under the **MIT licence**. It watches one GitHub repository, and optionally **Feishu** group chats. When an approved person asks for something, it opens a work item, does the job in its own session and folder, and **replies where you asked, for example with a pull request**. [(GitHub)](https://github.com/deepseek-ai/dsh-superagent-prototype)

```viz:flow

note: "Router and parallel Workers per AI Weekly's summary; the rest from the project README."
```

**The details that matter:**

- **The idea:** "minimise human attention". It acts **only when asked, or when a team rule allows**, and a web panel shows what needs a person.
- **Not a product (yet):** the README calls it a **research prototype**, mostly built by coding agents, that **"may still contain bugs"**. It runs as a bundle for **DeepSeek Harness**, DeepSeek's agent runtime.
- **Setup is agent-led:** you point your own coding agent at the repo and ask it to **follow SETUP.md** with you.
- **Traction:** AI Weekly, citing ShiftDelete, says it passed **4,000 GitHub stars within a day** and pitches it as a Claude Code rival. [(AI Weekly)](https://aiweekly.co/ai-news-today)

**Why it matters.** Coding agents are moving **from "you open a terminal" to "it lives in your team's tools"**, like a colleague you tag. But **anyone who can post in that chat can steer it**.
