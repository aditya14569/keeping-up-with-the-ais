# Part 1 · Learn one thing

## 🧑‍🏫 Mixture-of-experts: big models that only use a slice of themselves

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 5 · UNDER THE HOOD</span>

**A mixture-of-experts (MoE) model is many smaller sub-networks plus a little "router" that picks just two or three of them for each word. You get the knowledge of a giant model at the running cost of a much smaller one.**

**The plain-English version.** In Issue #33 we met the transformer: layers of attention followed by a block of maths called the **feed-forward network**, where much of the model's knowledge lives. A normal, **dense** model runs every token through all of that block. **An MoE model splits it into many "experts"** and adds a **router** that scores them and sends each token to only the top few.

So a model can have **1.6 trillion parameters in total** but only touch about 48 billion for any one token. **Total parameters decide how much it can know; active parameters decide how fast and cheap it runs.** That's why launch posts now quote two numbers.

**Analogy:** **a big Kota coaching institute.** It has 64 teachers, but a student's doubt doesn't go to all 64. **The front desk sends it to the two teachers best suited to it**: one for organic chemistry, one for exam tricks. The institute knows everything; each doubt costs only two teachers' time. The front desk is the router. And if the desk keeps sending everyone to the same star teacher, **the queue explodes**: that's the load-balancing problem.


**A real example.** Mistral's **Mixtral 8x7B** (2023) made MoE famous in open models: 8 experts per layer, 2 chosen per token. Mistral says it has **46.7B parameters in total but uses only 12.9B per token**, so it runs at roughly the speed and cost of a 13B model. [(Mistral)](https://mistral.ai/news/mixtral-of-experts/)

```viz:versus

right: {emoji: 🧩, title: Mixture-of-experts, points: ["Router picks **a few experts** per token", "Cost tracks **active** parameters, not total", "But **all experts must sit in memory**"]}
```

**The catch.** Active parameters save compute, **not memory**. All 1.6 trillion parameters still have to be loaded, because you don't know which experts the next token needs. That's why one guide to running Kimi K3.1 Pro locally warns you'll need to **clear about 1.6 TB of disk**. [(RunAIHome)](https://runaihome.com/blog/kimi-k3-1-pro-local-ai-hardware-guide-2026/)

**Why now?** Today's LongCat-2.5 is an MoE, and **Kimi K3.1 Pro's open weights are due tomorrow (4 Nov)**. [(Let's Data Science)](https://letsdatascience.com/news/moonshot-releases-kimi-k31-pro-api-open-weights-due-nov-4-786e160c) When you read "1.6T, 48B active", you now know which number matters for your bill.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Expert:** one of many small feed-forward networks inside a layer. Only **a few run per token**.
- **Router (or gate):** a tiny network that **scores the experts** and picks the top-k for each token.
- **Active vs total parameters:** active = **what one token actually uses**; total = everything stored.
- **Load balancing:** an extra training rule that stops the router **overusing a few favourite experts**.
</div>

<div class="box tryit" markdown="1">

<div class="box devs" markdown="1">
**🛠️ For devs: a toy MoE layer in 20 lines**

```python
import torch, torch.nn as nn, torch.nn.functional as F
class TinyMoE(nn.Module):
    def __init__(self, dim=16, n_experts=8, top_k=2):
        super().__init__()
        self.router = nn.Linear(dim, n_experts)   # scores every expert
        self.experts = nn.ModuleList(nn.Linear(dim, dim) for _ in range(n_experts))
        self.top_k = top_k
    def forward(self, x):                          # x: (tokens, dim)
        weights, picks = self.router(x).topk(self.top_k, dim=-1)
        weights = F.softmax(weights, dim=-1)       # mix the chosen few
        out = torch.zeros_like(x)
        for slot in range(self.top_k):
            for e, expert in enumerate(self.experts):
                mask = picks[:, slot] == e         # tokens sent to expert e
                if mask.any():
                    out[mask] += weights[mask, slot, None] * expert(x[mask])
        return out, picks
out, picks = TinyMoE()(torch.randn(5, 16))
print(picks)   # which 2 of 8 experts each of 5 tokens used
```

**Gotchas:** for hosting, **size your GPUs by total parameters** (memory) and **your throughput by active ones**. MoE models are also harder to fine-tune: routers can collapse onto a few experts, which is why recipes add a load-balancing loss. Real experts are full feed-forward blocks, not single linear layers.
</div>

## Top story 3 · GPT-6 Astra fixed a small model by editing its weights directly

<span class="tag learn">RESEARCH</span><span class="tag dev">FOR DEVS</span>

**What happened.** MIT CSAIL researchers (Rikiya Takehi, Jayden Teoh, Alex Zhang and Omar Khattab) describe **"weight-space programming"**: **GPT-6 Astra reads and edits another model's weights** from a plain-English spec, with **no gradient descent** (the usual way training nudges weights). [(AI Weekly)](https://aiweekly.co/ai-news-today)

```viz:bars

  - {label: "GSM8K", value: 67.1, display: "13.8 → 67.1", highlight: true}
  - {label: "IFEval", value: 62.3, display: "21.0 → 62.3", highlight: true}
note: "Authors' own results, as summarised by AI Weekly. Not yet independently reproduced."
```

**The details that matter:**

- **The bug:** Alibaba's tiny **Qwen3.5-0.8B** kept getting stuck **repeating itself**. Astra traced the looping to specific **directions in layers 15 and 19**.
- **The fix:** it removed those directions, changing **just 0.016% of the parameters**, and scores jumped on maths and instruction-following tests.
- **The source:** the write-up is on the lead author's **[project blog](https://rikiyat.github.io/blog/weight-space-programming/)**. We couldn't open it ourselves, so these details come via AI Weekly's summary.

**Why it matters.** It's like Issue #34's training story run backwards: instead of **training a behaviour in**, a model **found a bad behaviour and cut it out**. If it holds up, it links interpretability (looking inside models) to **practical repair**.
