# Part 1 · Learn one thing

## 🎟️ Trusted access and tiered model releases

<span class="tag learn">4 MIN READ</span><span class="tag learn">MODULE 7 · NEWER TECHNIQUES</span>

**The most capable AI isn't always released to everyone at once. Labs now hand out capabilities in tiers, and you prove who you are to climb them.**

**The plain-English version.** Some model skills are **dual-use**: the same ability that helps a defender find a bug helps an attacker exploit it. Instead of choosing between "release to all" and "release to nobody", labs create **levels of access**. Everyone gets the standard model. People who **verify their identity and their work** get fewer refusals. A small set of vetted partners gets the most permissive versions.

**Analogy:** a pharmacy. Paracetamol is **over the counter**. Antibiotics need a **prescription**. Some drugs are **hospital-only**. Same building, same chemistry, different gates depending on who's asking and why.

**The idea has a name.** Researcher Toby Shevlane called it **"structured access"** in 2022: developers allow **"controlled, arm's length interactions"** with a model, usually through a cloud API, instead of handing out the weights. [(arXiv)](https://arxiv.org/abs/2201.05159v2)

```viz:flow

headers: [Tier and who gets in, What changes]
columns:

```

**Real example 1: OpenAI.** Its Trusted Access for Cyber launched in February: individuals verify their identity, enterprises apply through their account rep, and an invite-only track exists for even more permissive models. [(OpenAI)](https://openai.com/index/trusted-access-for-cyber/) In April it added higher tiers with **GPT-5.4-Cyber**, a version with a lower refusal boundary, for vetted defenders. [(OpenAI)](https://openai.com/index/scaling-trusted-access-for-cyber-defense/)

**Real example 2: Anthropic.** Its Cyber Verification Program has **three tiers**, each with its own checks and user caps: [(Claude Help Center)](https://support.claude.com/articles/14604842-real-time-cyber-safeguards-on-claude)

| | Defense | Red Team | Specialized |
|---|---|---|---|
| For | Security ops, malware analysis | Pen testing, exploit work | Critical infrastructure testing |
| Who can apply | Orgs and individuals | Organisations only | Orgs, reviewed with US government |
| User cap | No default limit | Up to 75 | Up to 25 |
| Review target | ~2 days | ~2 weeks | No set target |

**Why now?** Story 3: from **November 20**, OpenAI requires approval for any service that resells **direct access** to its models. The gate is moving from the model to **the pipes that carry it**.

<div class="box jargon" markdown="1">
**📖 Jargon buster**

- **Dual-use:** a capability that helps and harms depending on who uses it.
- **Structured access:** letting people use a model through controlled channels without giving them the model itself.
- **KYC ("know your customer"):** identity checks, like the ones your bank runs.
- **Refusal boundary:** the line where a model says "I can't help with that."
</div>

<div class="box devs" markdown="1">
**🛠️ For devs: gate features by tier, fail closed**

```python
TIERS = {"public": 0, "verified": 1, "partner": 2}
NEEDS = {"explain_cve": "public", "write_fuzzer": "verified", "exploit_dev": "partner"}
def allowed(user_tier, task):
    need = NEEDS.get(task, "partner")   # unknown task -> strictest tier
    return TIERS[user_tier] >= TIERS[need]
for tier in TIERS:
    print(tier, [t for t in NEEDS if allowed(tier, t)])
# public ['explain_cve']
# verified ['explain_cve', 'write_fuzzer']
# partner ['explain_cve', 'write_fuzzer', 'exploit_dev']
```

A toy we ran in the sandbox. The key line is the default: **an unknown task gets the strictest tier**.

**Gotchas:** trusted tiers usually mean **more logging, not less**. Anthropic requires data retention for CVP members, and OpenAI says limits may apply to zero-data-retention use and third-party platforms. From **15 Dec**, Anthropic's Defense tier needs **phishing-resistant MFA** and no long-lived API keys.
</div>

## Top story 1 · Claude Ship: an agent that can approve your pull requests

<span class="tag hot">BIG DEAL</span><span class="tag dev">DEV</span><span class="tag try">TRY IT</span>

**What happened.** Anthropic launched **Claude Ship** on Monday, a set of agents that handle everything after a pull request (PR) is opened: **review it, fix it and, if your rules allow, approve it**. It pairs the existing Code Review with two new beta agents, **PR Steward** and **Claude Approvals**. [(TechCrunch)](https://techcrunch.com/2026/11/23/anthropic-launches-claude-ship-letting-ai-agents-review-fix-and-approve-code-changes/)

```viz:flow
title: "A PR's journey through Claude Ship"
headers: [Open, Review, Fix, Decide, Merge]
columns:
  - [{label: PR opened, sub: "by you or /ship"}]
  - [{label: Code Review, sub: "Quick · Standard · Deep"}]
  - [{label: PR Steward, sub: "fixes CI, conflicts", style: soft}]
  - [{label: Approvals, sub: "applies repo policy", style: accent}, {label: Human, sub: "for flagged paths", style: warn}]
  - [{label: Branch rules, sub: "GitHub still decides"}]
note: "Our diagram from TechCrunch and Unite.AI. PR Steward can push fixes but is designed never to approve or merge."
```

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **Separation of powers:** PR Steward can push fix commits, and after each one says **what changed and how to roll it back**. Type `@claude stop` to halt it. It can't approve. [(Unite.AI)](https://unite.ai/anthropic-launches-claude-ship-to-review-fix-and-approve-prs)
- **Your rules, in a file:** Claude Approvals reads a **policy written in plain language** in your repo: which paths need how many humans, and when Claude may approve.
- **Who gets it:** **Team and Enterprise** plans, **GitHub only**, billed by tokens on top of plan usage, with spend limits. Not available to orgs on Zero Data Retention or HIPAA setups.
- **The company's claim:** on the Claude Code team, merged PRs **more than doubled** from June to September and reverted changes fell by **over 40%**.

**Why it matters.** AI already writes much of the code; **human review became the bottleneck**. "Most teams want a person to approve every change," Anthropic wrote, but that's hard when agents write the lines. This is the first big tool to **hand approval itself to an agent**.

## Top story 3 · OpenAI now decides who can resell its models

<span class="tag dev">DEV</span><span class="tag watch">POLICY</span>

**What happened.** OpenAI's rewritten usage policies **took effect on 20 Nov**. Any **"model-access intermediary platform"** that lets third parties directly access OpenAI models must now get **"our prior review and approval"**. That reads as covering routers, gateways and aggregators. [(PPC Land)](https://ppc.land/openai-forces-ai-model-resellers-to-seek-its-approval-first/)

```viz:versus
left:  {emoji: ✅, title: "No approval needed", points: ["Your app uses GPT for its own features", "A support bot or doc generator", "Existing contract permissions"]}
right: {emoji: 🛂, title: "Approval needed", points: ["Routers and gateways serving others", "An endpoint where outsiders send any prompt", "Grey zone: shared internal gateways"]}
note: "Our summary of PPC Land, Beri and Cloud Security Alliance readings. OpenAI hasn't published examples or criteria."
```

<p style="break-after: avoid"><strong>The details that matter:</strong></p>

- **The carve-out:** the rule **"does not apply solely because an application integrates OpenAI models"** for its own features. Most apps are fine.
- **Missing pieces:** as of 21 Nov, PPC Land saw **no application form, criteria or approved list**.
- **OpenAI's reasoning:** **the same safeguards** however you reach its models. It's also building **SafetyIDs** to tell users apart in abuse probes anonymously. [(OpenAI)](https://openai.com/blog/broad-access-through-consistent-standards)
- **Also new:** no using OpenAI outputs to prepare **training data for rival models**. [(Beri)](https://www.beri.net/article/openai-usage-policies-november-20-ai-gateway-router-prior-approval-anti-distillation-training-data-ban-enterprise-checklist)

**Why it matters.** The Cloud Security Alliance calls it the first time a frontier lab has made **the routing layer itself a permissioned tier**. Gateways were your backup plan; now **one can be switched off**. [(CSA)](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-access-layer-gatekeeping-concentration/)
